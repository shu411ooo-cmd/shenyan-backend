# 2026-09-12 记忆系统风险测评

> 范围：本次审查（2026-09-11~12）中识别出的全部残留风险，按「发生概率 × 影响」排序。
> 已修复项不在此列（见 `docs/2026-09-12-quality-loop-handoff.md` 第一节）。
> 评级口径：🔴 需要近期处理｜🟡 可接受的带险运行，但要有监控或预案｜⚪ 记录在案，暂不动作。

## R1 🟡 召回「被提及率」无持久化 —— 质量闭环的最大盲区

- **现状**：recallDaily 是模块态计数器（[retrieval.js:130](file:///c:/Users/hbyll/shenyan-backend/lib/context/retrieval.js#L130)），每日一行 console.log 后清零。注入了多少她接没接话，离线无法还原。
- **影响**：「注入有效吗」这个问题永远只能靠当天的终端日志回答；趋势、回归都无从谈起。本次质量报告的召回侧只有注入量。
- **触发条件**：常驻成立。
- **缓解**：无。
- **建议**：加一张 `recall_daily` 表，day roll 时顺手 insert 一行（1 行/天，成本可忽略）。需要 migration，本期未做。**做之前先确认 Zeabur 日志保留期够不够撑过渡**。

## R2 🟡 自动连边的两个固有弱点（新功能自带的险）

- **错边入库**：温度 0 + 候选校验只能保证边「语法合法、端点存在」，不能保证「关系真实」。LLM 提了一条事实上不成立的因果，就会进联想扩展。
- **影响**：联想路径把不相关的记忆拽进上下文，沈晏说出「因为 A 所以 B」式的错话。概率低（提示词宁缺毋滥 + 最多 12 条/轮 + 30min 节流），但非零。
- **缓解**：`MEMORY_AUTOLINK=off` 一键关停；质量报告 C 节可看边量/类型分布异常。
- **建议**：先观察 2~4 周质量报告 C 节，若错边肉眼可见再考虑加人工审队列。**不要急着加审核层，那是过度工程**。
- 另：节流是**进程内**的，重启即重置。部署日连着重启几次会多跑几轮——可接受，别为它加持久化。

## R3 🟡 判官与 v3.0 改写的「对不对」无离线度量

- **现状**：判官放行率、改写忠实度，只能靠人翻日志。本次刻意没做 LLM 抽检（成本决定）。
- **影响**：判官悄悄变严/变松（比如模型版本漂移），只会表现为建桶速度渐变——质量报告 A 节能看到影子，但给不出因果。
- **缓解**：A 节「近 7/30 天建桶数」是唯一代理指标。
- **建议**：把 A 节建桶速度写进每周留档习惯；突变（比如周建桶数腰斩或翻倍）时再考虑开 LLM 抽检。

## R4 ⚪ provenance 仍是字符串标签

- **现状**：【实/悬/空】前缀 + attention 的 refs 雏形，净本 §7#1 已记录。
- **影响**：「沈晏为什么这么说」无法结构化审计；质量报告 B 节的 refs 口径是这条债的受益者也是受害者。
- **建议**：单独立项的大改造，别顺手做。做之前先定义 topicId 全链路契约。

## R5 ⚪ voiceifyMemory 不可审计 + 串行延迟

- 渲染结果只进内存缓存不落台账，渲染失败率、渲染风格漂移不可见；首轮未命中时每条记忆一次串行 LLM 调用，加在注入路径延迟上。
- **建议**：若要动，给 voiceify 的产出也写一行 prompt_injections（layer='voiceify'），顺手就接进了现有台账与质量报告；串行改并行是独立小优化。

## R6 ⚪ 无遗忘通路 / 表达不回流 / 第三层空转

- 三条都是**设计层面的已知缺口**，净本 §7 与 2026-09-12 审查均有记录；第三层空转是成本决定（keepalive 有意关闭），不是缺陷。
- 备忘：若 keepalive 重开，记得回头验证 pickWakeIntent 的 fail-closed（78409d5 已改）在真实唤醒路径上的表现——目前只有夹具覆盖。

## R7 ⚪ 台账 0 行观察（本地库）

- 本次干跑：本地 .env 指向的库 `prompt_injections` 整窗 0 行、近 30 天 7 场会话。两种解释：本地库滞后（大概率），或生产也在空转（小概率但严重——正是空转十天事故的形态）。
- **行动项**：对生产库跑一次 `node scripts/audit/memory-quality.cjs`，确认 B 节窗口非空。这是本测评唯一一条「现在就做」。

## 测评结论

系统当前无 🔴 级风险。最值钱的两件后续：**R1 加 recall_daily 表**（补上「被提及率」，质量闭环才算闭环）和 **R7 对生产库跑一次质量报告**（五分钟，排除最坏情况）。其余均可带险运行，监控靠每周留档的质量报告 JSON。
