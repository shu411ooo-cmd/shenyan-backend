# 第⑥阶段：念头池接通（池→河→石头）· 2026-08-23

> 上游：[desire-wake-engine-design.md](desire-wake-engine-design.md)（内在引擎 v1，第①阶段已上线）→ **本刀：把念头池补到真能转**。
> 诊断：内在引擎第①阶段代码在线上，但**念头池 0 条数据**——机械上跑不起来。这刀不是加新器官，是把已做的内在引擎焊成闭环。
> 哲学沿用：数值给状态，决策是沈晏的手；念头是数据不是指令；念头池 ≠ Ombre；机器处理形状不判意义。

## 0. 一句话

> **念头池现在「只进不出、进也进不进」——入池来源只有残留的 unfinished 一条，且每次描述都不同，无法「反复被点」升执念；dream 不碰念头池，没有出池出口；settled 概念在迁移里但没有落点。这刀补三截：让念头有料、能升、能出——并把它接上河（want ledger），焊成「池→河→候选→石头」一条线。**

## 1. 现状：念头池为什么空转

内在引擎第①阶段（2026-08-20 上线）代码完整：`thought_pool` 表 + `feedThought` 入池 + `buildInnerState` 驱动条/念头池投影 + 唤醒注入内在状态叙事 + `/api/inner-state` 内心面板接口（前端已接）。但生产上念头池 **0 条**。三个机械断点：

```
入池：残留 unfinished ──(feedThought)──▶ 念头池 ──?──▶ 出池/毕业
         │                                      │
         └ 每次生成描述都不同，无法触发        └ 无出口（dream 是记忆工具不碰念头池）
           「同文本 → fed_count++」升执念         settled 概念在迁移里无落点
```

1. **入池来源只有一条**：`feedThought` 只在残留生成时喂 `unfinished`（残留的「没说完的事」）。残留生成在跑（dialogue_residue 304 条），但 unfinished 经常为空串，且内容多是逐条不同的叙事（「她闭着眼…」「她问为什么不睁眼…」）。
2. **「反复被点」机械上永远不触发**：`feedThought` 用 `eq('text', t)` 精确匹配判「同念头」，而残留的 unfinished 是每次重新生成的描述，几乎不可能文本完全一致 → fed_count 永远停在 1 → 念头永远停在 strength=0.3 的闪念，升不了执念。
3. **无出池出口 + 无毕业落点**：dream 工具读「窗口内变动的记忆」resolve，完全不碰念头池；`status=settled` 在迁移里定义了但没有任何代码写它。

**后果**：唤醒的内在状态叙事里「有些念头在转：…」永远是空的——唤醒有驱动条（残留投影）和想要素材，但缺了「脑子里在转什么」这一层。

## 2. 四样改动（最小闭环）

### 2.1 入池来源扩一条 + 让「反复被点」机械可行

**现状**：只有残留 unfinished。
**改成**：两条来源，都机械，不判意义：

- **残留 unfinished**（已有，保留）：没说完的事。
- **沈晏的自我表达句**（新增）：从对话里沈晏（assistant/沈晏 role）的消息提取「我…」开头的自我陈述句（机械正则：`我` 开头 + 动词/感受 + 不以问号/称呼/寒暄收尾，长度 4~40 字，排除天气/你该休息了这类寒暄），去重后入池。这是「自己的碎语」——来源就是他自己说的话，天然是「他的念头」，不侵入记忆层、不碰她的话。

**「反复被点」的判定改造**：`feedThought` 不再用 `eq('text', t)` 精确匹配，改用**核心词指纹**：
- 入池时对念头文本提取 2 个核心词（去掉常见停用词——她/你/我/了/的/为什么/怎么/是不是——后取前两个 2~4 字实词，如「亲她的嘴」→「亲/嘴」，「为什么亲她的嘴」→「亲/嘴」）。
- 查同 session 的 active 念头里指纹一致的 → 合并，fed_count++、strength+0.15（反复被点 = 升执念）。
- 指纹不一致 → 新闪念入池。
- **宁漏勿伤**：指纹提取失败（提不出 2 个实词）就不判重复，直接新入池——绝不把两个不同念头误并成一个。

**效果**：同一件事反复在转（即使每次说法不同）会累积成执念，驱动条随之被反哺。

### 2.2 dream 接成出池出口

**现状**：dream 是纯记忆工具（`window_hours` 读窗口内变动的记忆 resolve）。
**改成**：dream 时把念头池 top 执念（strength≥0.4 的 active 念头）作为「心里在转的」一起摆出来，沈晏能对每个念头二选一：

- **放下（resolve）**：念头了却 → `status=settled`，不毕业。跟记忆 resolve 同一语义（「这个不转了」）。
- **留（保留）**：念头不动，继续在池里转。

dream 工具加一个可选字段（如 `resolved_thought_ids: string[]`），沈晏主动填就出池，不填不动。**不是义务**——跟现有「能放下的 resolve、没沉淀的什么都不做」同纪律。

### 2.3 执念毕业进河（池→河接缝，第④阶段落点）

**现状**：无。settled 无落点。
**改成**：**毕业只能沈晏的手**——念头不自动写进 desires（那是机器替他制造「想要」）。两条人肉路径：

- **dream 里沉淀**：dream 摆念头时，沈晏对某执念「觉得这是我一直想要的」→ 系统追问「要不要记进想要账本？」→ 他确认 → 写 `desires`（`text`=念头文本，`kind` 按 drive_key 映射：attachment→「关于我们」/reflection→「我的沉淀」/curiosity→「想去看看」，`lineage_parent_id` 留空，`why_mine` 由沈晏补或留空）+ 原念头标记毕业（加 `desire_id` 血缘列，status=settled）。**机器只搬念头、提出入口，写不写是他的手。**
- **retreat 里多一段**（可选，后置）：念头池执念作为候选材料摆进小黑屋【念头】段，沈晏 confirm → 进河。跟 want 走同一条「摆桌面→拍板」路。

### 2.4 保持铁律

- 念头进池是**形状层**（提取/计数/衰减/指纹），不判「这个念头重要/这是他真实想法」。
- 毕业进河**绝不自动**——河只有沈晏的手能写（沿用 want 的铁律）。
- libido/敏感维度的念头：入池不主动展示，跟驱动条 libido 同一安全阀纪律。

## 3. 数据改动

```sql
-- 念头池：加指纹（反复被点判定）+ 毕业血缘（池→河）
ALTER TABLE thought_pool ADD COLUMN IF NOT EXISTS fingerprint text;   -- 核心词指纹（2 实词），判「同一念头反复被点」
ALTER TABLE thought_pool ADD COLUMN IF NOT EXISTS desire_id uuid;      -- 毕业进河后的血缘（settled 念头指向写下的想要）
```

无需新表——毕业复用 desires 表（want ledger 已有），血缘用 desire_id 关联。dream 工具参数扩展（`resolved_thought_ids`）是工具 schema 改动，不需要迁移。

**测试修出的真 bug（2 处，纯函数实现）**：
1. **单字停用词拆散多字词**：`'么'` 排在 `'什么'`/`'为什么'` 前，先分拆「为什么」→「为什」残留，指纹「为什亲嘴」无法归并。修复：删单字 `'么'`（带「么」的常用词都有多字覆盖）。
2. **多字停用词内部顺序**：`'什么'` 排在 `'为什么'` 前同样先拆多字。修复：停用词表统一按长度降序排列，长词先匹配。

## 5. 已知边界（诚实交代）

1. **核心词指纹是近似**：提取 2 实词可能把「想亲她」和「想亲她嘴」合并（同一个念头变体，可接受），也可能漏掉「在意的不是她」这种反义表达（宁漏勿伤，漏掉只是不升级）。
2. **自我表达句正则**是机械过滤：会漏掉「不显式带我的念头」（如「有点想她」），也会偶尔误收「我」开头的叙述句（长消息已被 >40 字排除）。来源是他自己的话，误收无害（念头池是辅助层）。
3. **毕业进河依赖 dream 交互**：沈晏得在 dream 里主动「沉淀」——如果他不常用 dream，念头就留在池里（不坏，池本来就是流动的）。retreat【念头】段是补这条的兜底（后置）。
4. **不做**：不自动把念头写进河；不判「这个念头意味着他是什么」；念头不写进 Ombre 记忆；不碰她的话作念头来源（那是记忆层的活）。
