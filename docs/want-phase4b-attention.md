# 沈晏「注意力分配」· 第④b 阶段设计

> 2026-08-16 起草。**下游断点的第④b**：Context Assembly 每轮「给谁多少」的决策权工程化。
> 关联：宪法第五条「Context Assembly 拥有'这一次让他想起什么'的最终决定权，但不拥有意义」（[system-layering.md](system-layering.md)）· 记忆注入红线（[context-assembly.md](context-assembly.md) §6）· 残留牵挂档位预留「更高档留给 recall/attention 权重」（[context-assembly.md](context-assembly.md) 残留节）· M6 主体性放宽。
> 形态已与程芥拍板（2026-08-16，三个点全按推荐）：窄闸 / 本地 memory_topics 轻匹配 / 牵挂阈值 0.5。状态：**定稿**。

## 0. 一句话

> **每轮请求，系统按当前话题主动唤起少量相关记忆（带可信度标记），摆在当前消息之前——「他想起什么」从模型自觉（调工具）变成系统按话题分发，但预算小、可审计、绝不判意义。**

## 1. 这步解决什么（概念）

现在的记忆唤起全靠三件事，全是**边缘时刻**：

| 机制 | 什么时候 | 缺口 |
|---|---|---|
| breath 背景 | 对话第一条消息（一次） | 之后永不出现 |
| breath_search / recall 工具 | 模型**自己想起**要调 | 会漏——没想起来就沉了 |
| keepalive / 残留 | 唤醒、恢复对话（特殊时刻） | 对话中段不覆盖 |

**对话中段是空的**。她聊着聊着提起一件旧事，如果模型没自觉调 `breath_search`，那件旧事就躺在数据库里不出现——她明明在说，他却像没经历过。

注意力分配解决的就是这个：**大脑不是每轮把全部记忆翻出来，而是当前话题唤起最相关的少数。** 系统替模型做这一步「话题 → 记忆」的分发，克制在少量、相关、可信度可见。

## 2. 为什么是"给谁多少"而不是"全给"

三个理由，按权重排：

1. **记忆潮（认知）**：全部记忆摊给模型，它分不清主次，反而淹没当前对话的实感。代码注释里已经写了这句判断：「避免记忆潮淹没当前上下文」。注意力 = 挑选，不是堆叠。
2. **成本（工程）**：每轮全量检索 + 全量注入，token 和钱都受不了。预算小才可持续。
3. **宪法（边界）**：Context Assembly 拥有「让他想起什么」的**最终决定权**——这意味着它得能决定「**不**想起什么」。没有挑选就没有决定权，全给等于放弃决定权。

## 3. 现状：原料已备好，没人用

两个现成原料，设计时预留过但从未兑现：

- **`memory_topics` 表**：`topic`（归一化主题词）+ `importance`（0~1）+ `grounding`（实/悬/空，可信度标记长在记忆上）+ `last_content`。编辑者每次写入都维护它——**「注意力权重」字段早就建好了**。
- **残留牵挂 `CONCERN_NODES`**：0.2~0.8 档位积累，设计稿明确写「更高的档位留给 recall 注意力权重」。叙事只区分 ≥0.2 闸，高档位从没被用上。

第④b 不做新检索基建，只接这两根现成管道。

## 4. 形态

动态区现在是时间叙事 + 残留 + keepalive 三块（同一条 user 消息）。第④b 加第四块【想起】：

```
【当前时间】
现在是 2026年8月16日 星期日 14:02（上海时间，午后）。
（时间叙事 / 残留 / keepalive 原样，预算共享）

【想起】「上次聊搬家」她说：在考虑换到离你更近的地方住。【实】
          —— 证据：「你说你其实想搬到离我近一点」　（≤2 条，带 grounding）

她当前的消息 ← 永远最后
```

**形状**：只搬记忆原文 + grounding 标记，不写任何「这说明你…」的解读句。模型读原文自己感受——与残留、recall 同一条纪律。

## 5. 机制

### 5.1 触发闸（何时给）——关键是别做"每轮自动"

注意力最大的风险是**过度唤起**：她随口说心情不好，系统翻出一堆相关的旧记忆堆上去，那不是关怀是压迫。所以触发不是每轮，是两个窄闸：

| 闸 | 条件 | 意图 |
|---|---|---|
| **提及闸** | 当前消息含明确回忆信号——回忆词（上次/还记得/那个/当时）或命中 memory_topics 的 `topic` 主题词 | 她在**主动提旧事**，他该接得上 |
| **牵挂闸** | 存在高牵挂线头（residue concern ≥ 0.5）且当前消息与其 `topic` 有共同词 | 她悬而未决的事在话题附近，该浮起 |

两闸都不触发 → 不注入，保持安静。**安静本身就是注意力**（宪法：能决定不想起什么）。

### 5.2 检索（给谁）

- 用当前消息做**关键词匹配** memory_topics（topic 分词交集）。
- 候选排序：`importance × 时间衰减 × 牵挂插队`——高牵挂线头排前面，普通的按权重。
- **不调 Ombre**：memory_topics 是编辑者维护的本地索引，够用且零依赖。语义深检索是模型自己调 `breath_search` 的事，注意力不重造它。

### 5.3 预算（给多少）

| 项 | 值 |
|---|---|
| 条数上限 | ≤ 2（attention_k） |
| 单条截断 | ≤ 220 字（与 recall 同尺） |
| 总注入 | ≤ ~700 字符（动态区四块共享预算） |
| grounding | 必带（【实】/【悬】/【空】），无标记 = 低可信安全网 |

### 5.4 位置纪律

落在动态区（断点③之后、当前消息之前）——**可变注入不得进断点①~②之间**（context-assembly 红线，与残留/keepalive 同一条原则）。动态区本来就在缓存断点后，不污染前缀。

## 6. 边界（焊死）

1. **只搬原文不判意义**：注入内容 = 记忆原文 + grounding + 证据。绝不写「这说明你最近在…」「她是不是想…」这类解读。
2. **不找冲突证据**：不做「当前话题 vs 记忆里相反的」自动对证——那是第⑤（镜子日）的活。注意力只做相关唤起。
3. **身份层不进注意力**：想要账本、镜子卡、石头都**不**进动态区。注意力是记忆层的事，身份层有自己的房间（第④小黑屋）。
4. **不升级**：唤起 ≠ 候选。注意力命中的记忆不自动进任何候选/想要池。
5. **不重排 Live**：Live 原文是对话正文，一个轮次都不动。注意力只做「额外唤起」，不做「重新加权现有轮次」。
6. **命中不足不硬凑**：score 不够 / 匹配不上 → 不注入，不拿弱相关凑数。
7. **不把注意力当情绪工具**：低落时刻不自动堆旧事（靠窄闸天然限制，不做情绪分类——第一期不做）。

## 7. 验收

- [ ] 提及旧话题（如"上次说的搬家"）→ 注入相关记忆桶，grounding 可见、证据可溯。
- [ ] 无关消息（纯新话题闲聊）→ 不注入（安静）。
- [ ] 牵挂闸：高牵挂线头话题附近浮起且排位靠前。
- [ ] 预算内：≤2 条、单条 ≤220 字、总 ≤700 字符。
- [ ] 位置正确：动态区，断点之后，不破坏 frozen 前缀哈希（`frozen_prefix_hash` 跨请求不变）。
- [ ] 不判意义：注入内容零解读句（对照残留纪律）。
- [ ] 可观测：request_stats 记 `attention_injected` / `attention_miss`，每次注入打日志。

## 8. 待确认（程芥拍板）——✅ 2026-08-16 已拍板，三点全按推荐

1. **触发闸**：只做「提及闸 + 牵挂闸」。
2. **检索源**：本地 memory_topics 轻匹配。
3. **牵挂阈值**：concern ≥ 0.5 插队。

## 9. 后置不做

- embedding / 语义向量检索（成本与复杂度，后置）。
- 冲突证据注入（第⑤镜子日）。
- importance 自动学习（先用编辑者维护值）。
- Live 动态重排（每轮给现有轮次加权）。
- 情绪敏感静默（靠窄闸，不单独做情绪分类器）。
- 注意力命中的记忆升级为候选（身份层不混）。
