## §1 分区第 2 步：方法（照抄即可）

6 个域已全部完成，方法固定下来了。**每搬一块都按这五步，不要跳。**

### 步骤

1. **划边界**：找区块起止行（用 `// ===== ` 标记 + 下一个非本域路由定位）。
2. **依赖分析**（关键，别省）：用 `scripts/audit/dep.cjs`（用法 `node scripts/audit/dep.cjs <起始行> <结束行>`，已入库）看三件事：
   - 区内定义了什么
   - **区内符号被区外引用**（= 搬走会断，必须由工厂交出去）
   - 区内用到的区外符号（= 要注入的依赖）
3. **写模块**：统一形态是**工厂 + 显式依赖注入**：
   ```js
   module.exports = function createXxx({ supabase, ... }) {
     if (!supabase) throw new Error('createXxx: 缺少 supabase 依赖');
     const router = express.Router();
     ... router.get('/子路径', ...)
     return router;           // 或 { router, 别的要交出去的能力 }
   };
   ```
   **绝不用 `require('../server')` 反向引用** —— 那是循环依赖，CommonJS 不报错、只给
   `undefined`，运行到那行才 TypeError。本项目今天已经踩过三次同类静默故障。
4. **回填 server.js**：原位置换成 `app.use('/api/前缀', createXxx({...}))`，require 加到文件顶部那一串后面。
5. **验证**（三条缺一不可）：
   - `node -c` 两个文件
   - **`npm test` 52/52** —— 路由快照会逐条比对 84 条路由的「方法 + 完整路径 + 注册顺序」
   - `grep` 搬走的每个符号在 server.js 里**零残留**（有残留 = ReferenceError，但可能要到运行时才炸）

### 搬运脚本的写法
用 Node 脚本做机械替换（`app.METHOD('/api/x/y')` → `router.METHOD('/y')`），**每步下断言**：
路由数必须等于预期、改写数必须等于路由数、块内不许混进别的东西 —— 任一不满足就 `process.exit(1)` 整体中止。
搬运脚本本身是一次性的、没入库；照上面的描述重写即可，不复杂。常驻工具在 `scripts/audit/`。

⚠️ **不要用 bash heredoc 写这些脚本**：本轮多次遇到 heredoc 吃掉反斜杠（`\\b` 变成退格符）导致正则失效。用文件写入工具直接写 `.cjs`。

### 路由护栏（`test/routes.test.cjs`）
2026-09-09 从「正则扫源码」改成**运行时遍历 Express 路由栈**。原因：搬到 `app.use` 挂载后，源码正则看不见那些路由 —— backup 刚搬完两条路由就从快照里消失了。
坑：Express 5 不再把挂载前缀暴露在 `layer.path` / `layer.regexp` 上（藏进 `matchers` 闭包），所以测试里先给 `express.application.use` 打补丁，注册那一刻把前缀记到 router 函数上。

**快照是行为不变式。搬运时它应当纹丝不动 —— 如果变了，先怀疑自己搬错了，不要急着 `--update`。**

   - `processDueReplies` / `processDueCommentReplies` —— 被 `listen()` 里 15 分钟的 `setInterval` 调
   - `ensureMomentsBucket` —— 被启动时调
   - `storeChatKeepsake` —— 被聊天主链路（`handleChat`）调
   - `postAngelMoment` —— 2 处
   这些是「被外部调用的能力」而非「通用工具」，**应由工厂一并交出**，形态同 `routes/calendar.js` 的 `{ router, buildCalendarBlock }`。
3. **顺序问题**：日历的挂载点目前夹在 moments 路由中间，把它们劈成前后两段。全部搬到一个挂载点会**改变路由注册顺序** → 快照会变。

**已经先做掉的准备**：通用 LLM 调用（`callDeepSeek` / `callOpenRouter` / `callReplyModel` / `callVisionModel` / `parseJsonLoose` / `randomDelay`）已抽到 `lib/llm.js`，它们原本住在朋友圈区但不属于那个域。

## §4 踩过的坑（读这节最省时间）

### 关于这个项目
1. **PostgREST 的 `.select('a, b, c')` 只要一个列不存在就整条查询报错** → 配上 `if (error) return DEFAULTS` 就是**整组配置静默退默认**。已加 `warnConfigFallback` 一次性告警。
2. **`console.warn` 每轮都喊 = 等于没喊。** 注入台账写失败喊了十天没人看见。改用 `warnOnce(key, msg)`（server.js 里有）。
3. **`sessions.id` 是整数不是 uuid。** 新建表引用它时别写成 `uuid`。
4. **后端 `SUPABASE_KEY` 是 `sb_secret_` 开头的 secret key（绕过 RLS），前端不直连 Supabase。** 所以给表开 RLS 对后端零影响 —— 但如果哪天换成 publishable/anon key，开 RLS 会当场锁死应用。
5. **迁移不会自动跑**（`.env` 里没有 `PG_CONN_STRING`，`npm run migrate` 用不了），只能去 Supabase SQL Editor 手动贴。
6. **`settings` 表没有建表脚本**（面板手工建的），所以「迁移文件里没有某列」≠「该列不存在」，必须查库。

### 关于工具和方法
7. **不要用 bash heredoc 写含正则的 Node 脚本** —— 反斜杠会被吃掉（`\\b` → 退格符），脚本静默失效或报奇怪的语法错。用文件写入工具。
8. **`awk` 的正则里 `\<` `\(` 会告警并炸**，判断标识符边界用 Node 而不是 awk。
9. **判断「某符号还用不用」必须连裸引用一起数。** 本轮按 `grep 'callDeepSeek('` 裁剪 import，结果它是**作为依赖注入**传出去的裸标识符 —— 当场 ReferenceError。
10. **依赖分析脚本的计数要用 grep 调用点复核**，别直接信（本轮它报「区外 8 处」，实际是 1 处注入）。
11. **看命中率别用日聚合** —— token 加权会让一次冷启动全写盖过几十次高命中。要看**单请求分布的中位数**。
12. **「某机制在某个日期之后停了」，先问有没有输入**，别急着归因到那天的部署。（念头池 08-31 后没新增，我一度怀疑是那天的「入池收紧」，实际是她没聊天。）

### 四条通用查法（今天全部命中过）
1. **表里有没有行** —— 空表 = 上游从没写进来过（表达资格隔离就是这么发现的）
2. **计数分布是不是恒为 0** —— `settled 0 / graduated 0` 揭穿了念头池清扫从没跑过
3. **闸是不是永远同一边** —— 某个 gate 的两个分支只走过一边，另一边就是死代码
4. **拿真实值去 `.eq()` 探列类型** —— 只读就能验出类型错配（`session_id` 建成 uuid 那个）

现成工具在 `scripts/audit/`：`scan-reads.cjs` / `scan-writes.cjs` 扫「代码读写的列表里有没有」，
新增表或列之后值得重跑（它们是今天发现三个真 bug 的主力）。

### ⛔ 纪律（外包时尤其要写进任务单）

### ✅ 同一个洞已堵（2026-09-10 落码，**未部署**）

原来的 `baseRow` 降级**兜不住**，三条：①它自己仍带着 `keepalive_action` / `keepalive_meta` /
`memory_degraded` 三个较新的列——缺的若是这三个之一，两次插入都失败、**整行照样丢**；
②它把 `residue_mode` 丢了（降级即掉字段）；③失败信号只有一行 `console.warn`——正是教训 #2
「每轮都喊 = 等于没喊」，`prompt_injections` 空转十天就是这么发生的。

**改法**：PostgREST 报错**带列名**（实测 `column request_stats.xxx does not exist`），
所以从报错里抠出缺的那一列，**剥掉重试**——缺什么只丢什么，账本不再整段瞎。
新增 `lib/stats-row.js`（`missingColumnFromError` / `stripColumn` / `pickColumns` /
`insertRowResilient`），逻辑住 lib 里是为了能被单测拿假 insert 跑通，而不是只靠肉眼。
`recordRequestStat` 改成调它；失败与降级都收进 `warnOnce`（降级按缺的列集合分键）。

**认不出来的报错怎么办**：剥不动就退到「只写建表起就在的核心列」，尽量别丢整行；
连核心列都写不进才 `warnOnce` 喊一次「账本正在丢行」。**认不出列名时绝不猜**
（猜错会剥掉不该剥的列），这条有单测守着。

**护栏自证过**（照 auth-gate 的办法）：把 `missingColumnFromError` 临时弄瞎 → 10 条里
**4 条变红**（含 08-30 那条回归用例），还原后 62/62 全绿。
新增 `test/lib-stats-row.test.cjs`（10 条），`npm test` 从 52 → **62**。

⚠️ **仍未验证的一点**：单测用的是**假 insert**，实测的又是 **select** 的报错文案。
Supabase JS 在某些版本上 **insert** 会返回另一种（`Could not find the 'x' column of
'request_stats' in the schema cache`）——两种都写了正则，但**真的 insert 是什么文案，
只有线上真实插入能确认**。所以：**部署后要盯 `⚠️ request_stats 写入降级` 这条日志**，
看它是不是在正常工作（而不是悄默声地走了核心列模式）。
