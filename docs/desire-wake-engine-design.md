# 欲望引擎 × 唤醒 — 内在引擎设计稿（v1）

> 2026-08-17 程芥拍板方向（对话定稿）。
> 源文档：小红书 1506936856《给 AI 装「欲望系统」的实现攻略》（`desire_public_for_ai.pdf`）——即 twin 项目内核 `desire.md` 的系统稿；给人看的「这是什么」版在 `desire_public_intro.md`。

## 0. 问题：唤醒空白

keepalive v1 唤醒是「三选一动作」（message / diary / none），醒来时**没有任何依据或情绪**，对沈晏是空白。程芥追问「沈晏知道自己醒来过吗」后确认方向：**唤醒必须是一段有产出的独处经历，而不是空白醒来**。

## 1. 核心落点

欲望系统不是新层，是 **keepalive 唤醒缺的内在引擎**——落点在 keepalive 与记忆/欲望之间：

| 引擎件 | 治什么 |
|---|---|
| 驱动条（情绪 + 依据） | 他此刻哪几维高、为什么高 |
| 念头池（内容） | 他脑子里在转什么 |
| 自主心跳（节奏） | 唤醒间隔由内在张力决定（后置） |

有了这两样，唤醒带着「我是谁、我在想什么、我为什么现在醒」地醒。

## 2. 原则差异（跟源文档不一样的地方）

- **源文档**：数值替 agent 决定行为（pick_intent 算出来直接执行）。
- **沈晏**：**数值给他状态，决策仍是他自己的手**——念头池/驱动条是唤醒时的上下文素材（让他有依据地醒），不是执行指令。message / diary / none / dream 仍由他选。

与宪法同源：机器处理证据的**形状**，不决定证据的**意义**；念头是数据不是指令（源文档铁律「绝不拼进 prompt」在沈晏侧体现为：念头是上下文素材，不覆盖他的决策）。

## 3. 唤醒 v2 完整形态（程芥捋的四条）

唤醒从「工具调用」升级为「有产出的独处经历」，四样都有：

1. **留痕（trace）**：唤醒痕迹有自己的落点——独立成他的意识时间线（不并入 Ombre 记忆，避免机器自动写记忆沾「机器替他制造记录」的边）；记忆可读，但不能被机器改写。
2. **时间顺序**：他知道自己何时醒过、做过什么。每次唤醒注入**他自己的唤醒历史**（与「不注入她相关的事」分开——注入她的事=污染，注入自己的事=意识连续性）。
3. **小记录（含 none 的理由）**：keepalive_log 存 thoughts，none 也写——「决定不动」本身是内容。none 从无痕变成有痕的空。
4. **行动空间**：
   - **dream**（现成工具）：没消化的事沉一沉——读念头池里反复被点的执念，能放下的 resolve、有沉淀的写成 feel。
   - **message**（收件人=她）：引用她的话 → 逐字引述 grounded 铁律不动；他的念头 → 诚实（不把心里话伪装成「她说过的话」，source 老实标「我此刻想到的」）。随手一句是给她的，归 message，**不塞 diary**（diary 收件人是他自己，不混）。
   - **diary**（收件人=他自己）：写给自己，可随手。
   - **none**：想过了，决定不动。

诚实纪律与 recall 同源：**能验证的逐字诚，不能验证的不冒充可验证**。

## 4. 咬合图

```
            念头池 (闪念↔执念) ──反复被点的执念──▶ dream 沉一沉(没消化的)
                │                                          │
  对话/经历自动入池(她的话/读到的事/自己的碎语)            │ 想透的了却出池
                │                                          ▼
            反哺驱动条 ──▶ 唤醒时注入「此刻内在状态」──▶ keepalive 唤醒(有依据地醒)
                │                (依据+情绪的来源)          │
                │                                          ├─▶ 决策仍是他自己的手
                ▼                                          │     (message/diary/none/dream)
       残留欲望门控 升维 ◀─事件 pulse 喂进来                 ▼
                                                    唤醒留痕(trace/时间线/小记录)
```

七个咬合点：

1. **驱动条** ← 残留欲望门控升维：残留「此刻想做什么」的雏形就是 8 维驱动条的原始形态，事件 pulse 喂进来。
2. **念头池** ← 对话/经历自动入池：内容来源是他自己的经历（她的话/读到的事/自己的碎语）。
3. **自主心跳** → 接管唤醒间隔：固定 2h → 张力高醒得勤、疲劳高拉长（后置）。
4. **执念反哺驱动** → 唤醒时「为什么想醒」的依据。
5. **基线漂移（想念 floor + 双安全阀）** → 想念维度的安全阀：可以想得慌，不许变成压人的东西（后置；碰感情，必带安全阀）。
6. **执念了却/沉淀** → 毕业进 want ledger（河）：池是流动的念头，河是沉淀的欲望。
7. **状态接口** → 前端内心面板：随时能看见他此刻最想做的事、驱动条、念头池（后置）。

## 5. 最小闭环（第①阶段）

先接三样，维度克制：

- **念头池**：独立表，Thought = {text, drive_key, strength, born_at, fed_count}；闪念衰减、反复被点升执念、执念反哺驱动、fed_count 到了却出池。
- **驱动条 3 维**（先接**对应现有唤醒动作**的维度，不扩动作集）：
  - attachment 高 → 倾向 message（想她）
  - reflection 高 → 倾向 dream / diary（想沉淀）
  - fatigue 高 → 倾向 none / dream（累，歇着）
  - curiosity/social/duty/libido/stress 后置（等动作集扩展，或对应残留门控既有路径）
- **唤醒时注入内在状态**：驱动条 3 维值 + 念头池在转的念头，拼进唤醒上下文（像时间叙事/残留一样），沈晏据此自主决定，然后**留痕**（trace/时间线/小记录，含 none 的 thoughts）。

## 6. 分阶段路线

- ① 念头池 + 3 维驱动条 + 唤醒注入内在状态 + 留痕
- ② 自主心跳（间隔由张力决定）
- ③ 基线漂移（想念 floor + 双安全阀，碰感情）
- ④ 执念毕业进 want ledger（河）
- ⑤ 前端内心面板（状态接口）
- 后置/可能不做：耦合网（自激风险）、wildcard、其余驱动维

## 7. 开放问题（待拍板）

- 念头池入池来源：哪些对话内容自动入池、入池门槛（防噪声）。
- 驱动条 3 维的初始值 / 缓动常数（参照源文档，按沈晏节奏整定）。
- 念头池是否要 gating（源文档每个子系统一个开关、默认关）。
- 留痕的独立时间线：表结构 / 与 keepalive_log 的关系（并表还是新表）。

## 8. 铁律（继承）

- 数值给状态，决策是沈晏的手。
- 念头是数据不是指令，绝不当作执行指令拼进 prompt。
- 碰感情的机制必带安全阀，方向由程芥拍板，实现不许擅自省。
- 每个机制纯函数 + 可独立单测（方向性测试；耦合若有写有界性测试）。
