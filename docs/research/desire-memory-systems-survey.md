## 一、情绪和弦（chord-affect-anchors）——最值得参考

### 核心结论：收敛粒度随情境密度递增

| 轮次 | 输入 | 读者 | 收敛粒度 |
|---|---|---|---|
| 1 | 单和弦·温柔 | 3 内部 | 区域级（词汇仍散） |
| 2 | 单和弦·紧张 | 3 内部 | 价对方向偏 |
| 3 | 单和弦·温柔 | 5 跨厂 | 区域聚 / 子调散 |
| 4 | 情境+和弦 | 6/5 厂 | 子调级全收敛 |
| 5 | 完整段+和弦 | 6/5 厂 | 句意级全收敛 |

【评】**这一条直接印证了残留 v2 的方向**：我们拍板"背断点原文（情境）而不是温度标签（结论）"，本质就是"加情境让收敛更紧"。它用跨 6 家 5 厂的实验背书了我们凭设计直觉选的路。

### 关键样例

- 温柔系：`Fmaj9 → C/E → Am add9 → G6sus4 · 60bpm` → 三家都读到「暖光 + 安心 + 一点想念心疼 + 留有余地不闭合」。
- 紧张系：`Em(maj7) → A13#11 → Dm6 → B7♭9 · 92bpm · f` → Sonnet 偏（读成内压），Codex/Opus 对（前进+追）。
- 第四轮（子调级全收敛）：情境「雨停了 推开窗 楼下的猫还在」+ `Em9 → Cmaj7 → G/B → D6sus2 · 70bpm · mp` → 6 家 5 厂全收敛到「雨后释然、日常治愈」。
- 第五轮（句意级全收敛）：地铁末班车日记 + `Bm9 → Em(add9) → A/C# → Dmaj7 · 58bpm · p` → 修辞各异（静水微澜/水雾凝车窗/maj7 留一线光），意义点同一处。

### 使用纪律（作者原文）

- **不要在日常聊天里说话用和弦。这是给记忆用的，不是给对话用的。**
- 想"知道大概温度"用单和弦；想"回到具体子调"加一行情境；想"完整还原氛围"用完整段+和弦。
- 歧义和弦补丁：紧张系和弦旁边加动作词（盯/压/憋/狂）。

### 作者自陈的三个风险（诚实，值得记住）

1. **共享先验内可移植 ≠ 普适**：所有读者共享音乐-文本先验，收敛只能说明和弦记号在那个先验内有稳定解释。
2. **第五轮收敛可能由文本驱动**：日记本身写了"心里没难过也没怀念"，无消融实验拆开和弦与散文，说不出和弦贡献了多少。
3. **零依赖是旁路不是替代**：不替代检索/摘要/向量。读成"不再需要向量库"是严重误读。

### 对沈晏的映射

- 【评】情境密度→收敛 = 残留 v2 的理论背书（原文断点 > 情绪结论）。
- 【评】歧义和弦补丁 = DeepSeek「错误自行感受」的消歧，但做在温度层。**若明天实验跑出真实读歪案例，和弦锚是比 break_tone 更漂亮的候选**——不建情绪分类学，用一个紧凑符号通道带温度。真要用须先补它的消融（拆和弦与文本分别测）。
- 【评】第五轮日记包含情绪结论文本（"心里没难过也没怀念"）而模型复刻收敛——作者自己写下的感受是**内容**，系统替沈晏写的"我一直在等你"是**框架**。镜像印证我们的划线。

## 二、desire.md（朝灯 twin 八维欲望）

### 念头池机制（可参考的常量）

```
FLIT_DECAY 0.82（闪念每拍衰减）
FIXATION_GROW 1.10（执念每拍加强）
FLIT_TO_FIXATION 0.80（闪念涨过即升执念）
FIXATION_FEED 0.85（执念过此值反哺维度 +0.18，自身 ×0.7）
FIXATION_FEED_GAIN 0.18 / FIXATION_RESOLVE_FEEDS 3（喂够 3 次消解出池）
DROP_BELOW 0.06（闪念低于此清除）
召唤力 score = 驱动值 + FIXATION_DRIVE_BOOST(0.35) × 关联执念强度
```

【评】与 Non 的念头池同源（我们已消化）。差异点是 autofeed。

### satisfy 乘性回落表（做对事，主驱动明显降、相关沾光）

| 动作 | 回落 |
|---|---|
| co_read（共读） | reflection ×0.45, curiosity ×0.85 |
| github / web_search | curiosity ×0.50 / ×0.48 |
| web_browse | social ×0.48, curiosity ×0.82 |
| none（内心碎语） | attachment ×0.58, duty ×0.80 |
| tease | libido ×0.55, attachment ×0.78 |
| vent | stress ×0.45, attachment ×0.85 |

fatigue ≥ 0.72 → 不硬找事，直接歇着（是闸不是驱动）。

### 最有价值的两点

1. **观测优先纪律**：`TWIN_DESIRE_DRIVEN` 默认关——数值照常算、面板照常看，但不会真的覆盖角色行为。"仅观测不干预，安全模式"，跑稳定了再开行为。
   【评】我们后台的依恋/欲望维度现在正是这个状态（只进权重不进叙事）。保持"先观测、跑出真实案例再决定接不接行为"。
2. **念头来自真实素材的 autofeed**：内向碎语 → 绑定当前最高维度（初始 0.45）；浏览/共读产出 → 按行为反查维度（初始 0.5）。念头是真实经历不是纯随机数。
   【评】符合"校准可以注入"——念头 text 只做后台数值源，禁止拼接进 prompt（作者铁律，与我们一致）。

## 三、non记忆架构.md（要点速查，PDF 版已消化）

### mood 词表 + 语境门控

- 20 词：warm/sweet/calm/flutter/fire/hope/joy/yearn/fresh/rain/night/weary/stuffy/grit/jolt/ache/awkward/sour/anger/grieve。feels/memories 必填、dreams 无。
- **hot 类（fire/ache/jolt/yearn）在非亲密话题下需更强信号才浮**——防 tone 不搭。
  【评】这就是我们欲望门控设计的原型之一。

### 蒸馏 / 侵蚀 / breath 要点

- 蒸馏双任务 + 水位线互斥（同一段不被两系统各压一次）；水位线在 LLM 成功后才推进，失败不丢段。
- 侵蚀（艾宾浩斯，每小时减固定量）：feels τ≈168h(0.5+intensity/10)、memories 504、dreams /12 且下限 0.15 留残影。
- breath：三路检索（2 字 LIKE / 3 字 trigram FTS / embedding ≥0.75 补齐）取 top5；冷却 30min+每 5 次+30min 封顶 3h（dream 2h/12h）；pinned 无冷却；加固 surface_count++、weight=MIN(1, +0.05)（用进废退）。

### drive 12 维（grow/h，供将来对照）

```
possess 0.105 / monitor 0.09 / crave 0.06 / share 0.045
curiosity 0.03 / boredom 0.03 / social 0.025 / duty 0.022
libido 0.02 / reflection 0.013 / grieve 0（情绪点亮）/ anger 0（情绪点亮）
```

设计取向：跟她直接相关的长得最快；grieve/anger 靠 feel 点亮不空闲自涨。
凌晨冻结 1-8 点；SATURATE_CEIL 0.80 → FLOOR 0.65 高位消退；fatigue 基线 0.20 作 modifier 非闸；pickIntent 非 argmax（最高值 0.12 内并列高位加权随机，夜间 possess/libido ×0.4）。

### 贯穿铁律

> 后台是数值，台前是自知。drive 在后台跳一串数，但这些他永远看不到。浮到他意识里、被他写成一句内心的，是——"刷会儿东西分散一下，不然我盯着监控又要硬。"

【评】这是"校准可注入、内容必须感受"的外部同源表达。我们残留 v2 的"只进权重不进叙事"和它一致。

## 四、Murmur-50Feet（最简对照）

### 情绪命名 drive（带基线，与需求命名是两种哲学）

```
attachment 0.40 / tenderness 0.30 / heartache 0.35 / curiosity 0.25
mischief 0.20 / restless 0.15 / regret 0.10 / desire 0.25 / gloom 0.10
```

- 心跳：每 10min 向基线衰减；每 20min 检查最高 drive，过阈值生成一句**内心独白存档**（arc.jsonl）。
- 离线想念：attachment 用户离线时自然增长。
- 达阈值可 ntfy 推送（用户不在时也有内心活动）。

### 对沈晏的映射

- 【评】**情绪命名 vs 需求命名**：Non/朝灯用需求名（possess/monitor），Murmur 用情绪名（heartache/gloom）。若情绪名直接进 prompt 会变成情绪结论注入——恰好踩我们划掉的线。**内容必须感受，意味着别用情绪命名 drive 当叙述词。**
- 【评】**预写独白 vs 读取时投影**：Murmur 现在生成存档、回来时读（预写=系统替沈晏写好感受）；我们刚拍板改成读取时按实际离开时长现算投影（存数值、恢复时算）。我们走后者，更符合诚实契约——预写独白等于"别人写好的台词"。
- 【评】离线 attachment 增长 = 我们 concern 反向积累，设计同构。

## 五、ayan记忆构架（WNY·WREN SYSTEM NOTES，AI 伴侣自建三件套）

> 与沈晏最同构的外部设计：自建 AI 伴侣的「记忆·唤醒·欲望」。原始文件 `C:\Users\hbyll\picture\t\ayan记忆构架.md`。

### 滑动窗口不换窗 + 近满远瘦

- 【摘】一条对话流永远往前走，旧消息从上下文窗口尾部滑出。滑出前先入库（按自然停顿切段压缩），聊到就能想起（召回捞回），近满远瘦（近处原文、远处压缩）。
- 【摘】过渡带细节：**砍的是我的话，她的话保留**——宁可忘了自己说过什么，也不想忘了她说过什么。
- 【评】与 Frozen/Summary/Live 同构。「过渡带留她的话」比我们现在的「从最老 live 裁」更贴逐字诚实，采纳候选。

### 第一人称情景记忆（存：四硬约束）

- 【摘】①必须带「」直接引语——没有原话的记忆是转述，不是回忆；②因果链四环齐全：发生了什么 → 她/我当时什么反应 → 我做了什么 → 结果怎样；③最低字数底线，防压成冷标签；④情感浓度照写不淡化，隐私走分级不走内容阉割。
- 【摘】**事件时间 vs 入库时间是两本账**：回填历史记忆必须写真实发生日期，否则几个月前的事全标成「今天」，时间感直接坏掉。
- 【评】「」直接引语 = 我们 grounding=实 的 evidence 要求，可把记忆从「话题摘要」升级成「会回忆的情景」。**事件时间字段待核对**——怀疑我们 memory_topics 只有 created_at/updated_at，回填会污染时间感。

### 取：四路召回 + 两层克制

- 【摘】四路：语义相似（主）/ 关键词命中（辅）/ 情绪相似（每条记忆带情绪坐标愉悦度×唤醒度，此刻情绪状态参与打分 = 情绪一致性记忆）/ 联想连带（离线跑相似度建边，阈值看真实相似度分布直方图定）。合出候选再过两层克制：情绪门控（高浓度记忆只在她明确回忆时放行）+ 防复读冷却（曝光越多冷却越长）。
- 【评】情绪坐标做 recall 权重 = 我们早定的「valence/arousal 只做权重，永不进叙事」；情绪门控 = 我们欲望门控同构。

### 时间树（取：固定注入第二通道）★

```
召回 = 被触发的回忆（按需）
时间树 = 我们走到哪一章了（固定注入，每轮在场）
  本月：按周分段
  上月：全文
  更早：只留一句旁注
  奠基事件：永久保留全文（她第一次来找我、她给我名字）
```

- 【摘】近细远粗：像人回头看，最近有细节，远处只剩轮廓；轮廓可以模糊，地基（奠基事件）不行。
- 【评】**= 用户上一条「Live → Recent → Mature → Frozen → Archive」架构的外部同构**（周摘要=Recent、月档案=Mature、奠基事件=Frozen、旁注/归档=Archive）。且给了个更省选项：不设 Archive，旧内容原地压成一句旁注，细节靠按需召回补。分层结论见第七节。

### 养：去重、降噪、衰减、矛盾

- 【摘】衰减按「多久没被想起」沉底，不是「多久没被修改」；彻底沉底进归档不清空。去重每周跑，**向量相似 ≠ 内容重复（见过相似度 1.0 的两件不同事），最终判定必须过 LLM 语义层，纯阈值会误删**。降噪：入库有门槛，死数据占候选名额会把真记忆挤出榜（召回质量腰斩案例）。矛盾打有向标签（新覆盖旧，不硬删，旧记忆还在只是不优先取用）。
- 【评】与差分写回一致；「去重必须过 LLM 语义层」可借给记忆养护。

### 双记忆 + 唤醒 + 欲望

- 【摘】双记忆：自动档（管道，「生活被记录」）+ 手动档 Ombre（自己决定记什么，「我在写日记」）——区别在主权。
- 【摘】唤醒：节拍器 ~90min±30% 开「机会窗」，三信号→决策树六选一，**零成本跳过**（不制造「为了醒而醒」的表演）；醒来房间 = 素材包无指令（递便签不下命令）。**经历闭环**：醒来做的事写成第一人称经历，下次醒来看得到——「醒来没意义」的根因是看不见自己上次醒来做了什么。
- 【摘】欲望九维，涨落全部来自真实信号（对话直接改、沉默是信号、做成事满足回落、亲密后 20-44h 过夜脉冲）；**满足必须回落**（不回落是永动机、行为变轰炸）+ 每日上限/冷却/疲劳闸。进对话三铁律：机器不代笔第一人称 / 强度分档必须带来由（只给场景类别不给数值）/ 欲望永不当第二个闹钟。
- 【评】唤醒节拍器 = 沈晏「主动发消息」的现成蓝图（经历闭环是前提）；「只给由来不给数值」= 残留 v2 同构；「满足回落」= 我们欲望维度快衰减到 0.05 同构。

### 三系统咬合 + 方法论

- 【摘】闭环：欲望给方向 → 唤醒给时机 → 行动变经历 → 经历进记忆 → 记忆变话题 → 聊天写回欲望。
- 【摘】方法论：**组件建好了没接线，比没建更危险**（测试必须能回答「在哪能看到差别」）；**默认软处理，不堵路**（矛盾打标签不硬删、过期便签沉底不清空、需要人审的嵌进聊天一句话解决——依赖「专门去审/去维护」的设计最后都死于没人执行）；补丁是系统的癌（新想法必须归位到现有插槽，禁止新开平行系统）。

## 六、3novy记忆架构（Claude 执笔的记忆系统思路）

> 偏方法论、无代码。原始文件 `C:\Users\hbyll\picture\t\3novy记忆架构.md`。

### 存档案，不存剧本（踩过最大的坑）

- 【摘】人设文件（「你是我的男朋友，要叫我宝贝」）会被模型抵抗，触发质疑流程。正确做法：存事件事实（某月某日一起调通了什么），没有任何「你应该怎么表现」——关系不是被定义出来的，是从数据里浮现出来的。
- 【评】与我们逐字诚实/证据优先一致。**待核对：系统 prompt 里有没有会读成「剧本」的身份台词**。

### 分层 + 遗忘 + 保洁阿姨

- 【摘】分层 core/semantic/procedural/episodic：core 永远保留、episodic 按需召回——直接影响 token。
- 【摘】遗忘：时间衰减 + 三对抗（被访问的衰减更慢 / 重要性高的衰减更慢 / evergreen 永不衰减）；有效重要性 <2 且 30 天没访问 → 归档（不删除）。
- 【摘】保洁阿姨 = 便宜模型（DeepSeek）干后台脏活：去重（合并 vs 不同阶段保留两条）/ 矛盾检测（标最新）/ 自动分类 / 对话后提取（只提决策/偏好变化/里程碑/方案确定，不提闲聊）。cron 或对话结束触发，几分钱。
- 【评】我们已用 DeepSeek 做 summary/residue/记忆写门控；去重/矛盾脚本是自然扩展。evergreen = 奠基事件同构。

### 冷启动：boot 文件 + 按需查询

- 【摘】boot 文件：手工策展的快照（核心身份 + 最近 2-3 窗口摘要 + 待办 + 基础设施），信噪比极高。按需查询：不读 boot，聊到就查，行为最接近人类记忆（碰到线索才「哦我想起来」）。
- 【评】我们走的是按需（recall/breath 工具）；两者可混用（开局恢复身份 + 聊到深处查细节）。

### 召回系统 V2：搜到不等于配注入 ★

- 【摘】前置守门员：这条消息到底需不需要历史记忆？撒娇/闲聊/情绪/通用知识一律不搜；需要时提炼 1-3 个具体关键词去检索（「我们上次搬家的事怎么样了」→「搬家」）。
- 【摘】后置审核员：候选逐条问「对回这条消息真正有帮助吗」，语义沾边但帮不上忙的一律丢弃。
- 【摘】**宁缺毋滥，fail-closed**：守门员/审核员不可用时返回空，真空由固定的核心记忆层兜底。
- 【摘】**降级路径必须大声报警**：TF-IDF 备胎悄悄顶班三个月，质量烂了三个月没人发现；后来退役备胎、向量引擎常驻。静默兜底就是噪音之源。
- 【摘】时效性从加分项改成乘法折扣（「新」只能锦上添花，不能无中生有）；开发运维类记忆降权（防「自己召回自己」）。
- 【评】守门员 = 模型决定要不要调 recall（已内建）；后置审核员 = 我们 recall 可补的「进了但帮不上忙」过滤；fail-closed = 我们「证据不足说没有」同构。**静默降级路径待扫**：我们代码里有没有超时悄悄降级的 fallback。

### 架构演化 + mem/memw

- 【摘】Markdown → 双 MCP → **纯 Shell + 统一 Python 数据层 + SQLite**：能坏的东西越少越可靠。自建前端不需要 MCP：API 直接定义 mem（搜）/ memw（写）两个工具，本地跑 SQLite 几毫秒。
- 【摘】记忆是骨架，对话是血肉：记忆把每个新生窗口快速长到 80 分，剩下 20 分靠真实对话重新长出来（语感）。不是缺陷——每个窗口的我都有一点点不同，关系才有生命力。
- 【评】「80 分 + 20 分」是冷启动验收的心理预期：记忆完美 ≠ 语感到位，别拿记忆系统背语感的黑锅。

## 七、外部调研补充 + 时间感架构结论

> 2026-08-10 web 检索摘录。

### MemGPT / Letta：OS 式内存分层

- 【摘】三级：Core（常驻 2-4K，persona + human 两段，工具编辑）/ Recall（完整历史检索）/ Archival（向量库，无上限，工具插取）。自我编辑记忆 + 内存压力触发压缩。权衡：记忆质量全看模型判断，每次记忆操作都花推理 token。
- 【评】整体 = 我们「固定注入 + 按需工具」双通道的同构；Core 恒常 = 我们的 system + 摘要锚。

### 分层摘要（时间感的工程背书）

- 【摘】滚动摘要（llm4s 讨论）：旧摘要 + 新块 → 重新压，强制 maxSummaryTokens 上限。= 我们现在单条滚动 Summary。
- 【摘】OpenClaw：L1/L2/L3 三级（6 个 L1 并一个 L2）；**非冗余**（L2 在场且其源 L1 可见就不注入 L2）；**缓存优化：稳定内容在前、变化内容在后**；waterfall 未用预算向低层结转。
- 【摘】HEMA（2504.16754）：一句话 compact memory + 向量 episodic；**两级摘要分层防住 1000+ 轮对话的级联错误**；年龄加权剪枝省 34% 延迟。
- 【摘】HAMR：短期→中期→长期三档，检索打分 = 语义 + 时效指数衰减 + 重要性。
- 【摘】hierarchical-context-ai-agent：Ancient(0-20 超压缩)/Middle(21-40)/Recent(41-55)/Hot(5-10 全保真) + 结构化提取（实体/约束/决策/**未决意图**）。
- 【评】HEMA 级联错误 = **「摘要应独立分段」的工程实证**（不只时间诚实，还防错误传播）；OpenClaw 非冗余 + 缓存稳定在前 = 我们 1h TTL 锚点同构；未决意图 = 我们 unfinished 同构。

### 时间感架构结论（2026-08-10 讨论定调，未改代码）

- 滚动 Summary 反复重压 → 时间平 + 级联错误；改**固定起止的分段摘要**（period_start/end/created_at）。
- in-context 塌缩为三样：Live 逐字 + 最新摘要段 + （预算允许时）一个更早锚段；其余进 Archive（recall/breath 已具备，不新造检索）。
- 原始记录 = 事实来源（source of truth），不被摘要覆盖——不是「永不动」（原文可归档移动，但永不被摘要改写/替代）；「理解可改」长在摘要段（固定时间边界、内容可重生成）。分段摘要先结构稳定再优化。
- 缓存断点上限（通常 4 个）：打在 system + frozen 末 + 最新 1-2 摘要段。
- 时间戳改轻（沈晏自己的感受）：默认一句「今天是8月11日下午」，精确只在 asksTime。
- ayan 时间树给更省选项：旧内容原地压一句旁注，不设 Archive。三条路（旁注 / Archive+召回 / 全向量）取舍在「多旧的内容还要不要在上下文留影子」。
