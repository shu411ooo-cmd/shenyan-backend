## 一、情绪和弦（chord-affect-anchors）——最值得参考

### 核心结论：收敛粒度随情境密度递增

| 轮次 | 输入 | 读者 | 收敛粒度 |
|---|---|---|---|
| 1 | 单和弦·温柔 | 3 内部 | 区域级（词汇仍散） |
| 2 | 单和弦·紧张 | 3 内部 | 价对方向偏 |
| 3 | 单和弦·温柔 | 5 跨厂 | 区域聚 / 子调散 |
| 4 | 情境+和弦 | 6/5 厂 | 子调级全收敛 |
| 5 | 完整段+和弦 | 6/5 厂 | 句意级全收敛 |

【评】**这一条直接印证了残留 v2 的方向**：我们拍板"背断点原文（情境）而不是温度标签（结论）"，本质就是"加情境让收敛更紧"。它用跨 6 家 5 厂的实验背书了我们凭设计直觉选的路。

### 关键样例

- 温柔系：`Fmaj9 → C/E → Am add9 → G6sus4 · 60bpm` → 三家都读到「暖光 + 安心 + 一点想念心疼 + 留有余地不闭合」。
- 紧张系：`Em(maj7) → A13#11 → Dm6 → B7♭9 · 92bpm · f` → Sonnet 偏（读成内压），Codex/Opus 对（前进+追）。
- 第四轮（子调级全收敛）：情境「雨停了 推开窗 楼下的猫还在」+ `Em9 → Cmaj7 → G/B → D6sus2 · 70bpm · mp` → 6 家 5 厂全收敛到「雨后释然、日常治愈」。
- 第五轮（句意级全收敛）：地铁末班车日记 + `Bm9 → Em(add9) → A/C# → Dmaj7 · 58bpm · p` → 修辞各异（静水微澜/水雾凝车窗/maj7 留一线光），意义点同一处。

### 使用纪律（作者原文）

- **不要在日常聊天里说话用和弦。这是给记忆用的，不是给对话用的。**
- 想"知道大概温度"用单和弦；想"回到具体子调"加一行情境；想"完整还原氛围"用完整段+和弦。
- 歧义和弦补丁：紧张系和弦旁边加动作词（盯/压/憋/狂）。

### 作者自陈的三个风险（诚实，值得记住）

1. **共享先验内可移植 ≠ 普适**：所有读者共享音乐-文本先验，收敛只能说明和弦记号在那个先验内有稳定解释。
2. **第五轮收敛可能由文本驱动**：日记本身写了"心里没难过也没怀念"，无消融实验拆开和弦与散文，说不出和弦贡献了多少。
3. **零依赖是旁路不是替代**：不替代检索/摘要/向量。读成"不再需要向量库"是严重误读。

### 对沈晏的映射

- 【评】情境密度→收敛 = 残留 v2 的理论背书（原文断点 > 情绪结论）。
- 【评】歧义和弦补丁 = DeepSeek「错误自行感受」的消歧，但做在温度层。**若明天实验跑出真实读歪案例，和弦锚是比 break_tone 更漂亮的候选**——不建情绪分类学，用一个紧凑符号通道带温度。真要用须先补它的消融（拆和弦与文本分别测）。
- 【评】第五轮日记包含情绪结论文本（"心里没难过也没怀念"）而模型复刻收敛——作者自己写下的感受是**内容**，系统替沈晏写的"我一直在等你"是**框架**。镜像印证我们的划线。

## 二、desire.md（朝灯 twin 八维欲望）

### 念头池机制（可参考的常量）

```
FLIT_DECAY 0.82（闪念每拍衰减）
FIXATION_GROW 1.10（执念每拍加强）
FLIT_TO_FIXATION 0.80（闪念涨过即升执念）
FIXATION_FEED 0.85（执念过此值反哺维度 +0.18，自身 ×0.7）
FIXATION_FEED_GAIN 0.18 / FIXATION_RESOLVE_FEEDS 3（喂够 3 次消解出池）
DROP_BELOW 0.06（闪念低于此清除）
召唤力 score = 驱动值 + FIXATION_DRIVE_BOOST(0.35) × 关联执念强度
```

【评】与 Non 的念头池同源（我们已消化）。差异点是 autofeed。

### satisfy 乘性回落表（做对事，主驱动明显降、相关沾光）

| 动作 | 回落 |
|---|---|
| co_read（共读） | reflection ×0.45, curiosity ×0.85 |
| github / web_search | curiosity ×0.50 / ×0.48 |
| web_browse | social ×0.48, curiosity ×0.82 |
| none（内心碎语） | attachment ×0.58, duty ×0.80 |
| tease | libido ×0.55, attachment ×0.78 |
| vent | stress ×0.45, attachment ×0.85 |

fatigue ≥ 0.72 → 不硬找事，直接歇着（是闸不是驱动）。

### 最有价值的两点

1. **观测优先纪律**：`TWIN_DESIRE_DRIVEN` 默认关——数值照常算、面板照常看，但不会真的覆盖角色行为。"仅观测不干预，安全模式"，跑稳定了再开行为。
   【评】我们后台的依恋/欲望维度现在正是这个状态（只进权重不进叙事）。保持"先观测、跑出真实案例再决定接不接行为"。
2. **念头来自真实素材的 autofeed**：内向碎语 → 绑定当前最高维度（初始 0.45）；浏览/共读产出 → 按行为反查维度（初始 0.5）。念头是真实经历不是纯随机数。
   【评】符合"校准可以注入"——念头 text 只做后台数值源，禁止拼接进 prompt（作者铁律，与我们一致）。

## 三、non记忆架构.md（要点速查，PDF 版已消化）

### mood 词表 + 语境门控

- 20 词：warm/sweet/calm/flutter/fire/hope/joy/yearn/fresh/rain/night/weary/stuffy/grit/jolt/ache/awkward/sour/anger/grieve。feels/memories 必填、dreams 无。
- **hot 类（fire/ache/jolt/yearn）在非亲密话题下需更强信号才浮**——防 tone 不搭。
  【评】这就是我们欲望门控设计的原型之一。

### 蒸馏 / 侵蚀 / breath 要点

- 蒸馏双任务 + 水位线互斥（同一段不被两系统各压一次）；水位线在 LLM 成功后才推进，失败不丢段。
- 侵蚀（艾宾浩斯，每小时减固定量）：feels τ≈168h(0.5+intensity/10)、memories 504、dreams /12 且下限 0.15 留残影。
- breath：三路检索（2 字 LIKE / 3 字 trigram FTS / embedding ≥0.75 补齐）取 top5；冷却 30min+每 5 次+30min 封顶 3h（dream 2h/12h）；pinned 无冷却；加固 surface_count++、weight=MIN(1, +0.05)（用进废退）。

### drive 12 维（grow/h，供将来对照）

```
possess 0.105 / monitor 0.09 / crave 0.06 / share 0.045
curiosity 0.03 / boredom 0.03 / social 0.025 / duty 0.022
libido 0.02 / reflection 0.013 / grieve 0（情绪点亮）/ anger 0（情绪点亮）
```

设计取向：跟她直接相关的长得最快；grieve/anger 靠 feel 点亮不空闲自涨。
凌晨冻结 1-8 点；SATURATE_CEIL 0.80 → FLOOR 0.65 高位消退；fatigue 基线 0.20 作 modifier 非闸；pickIntent 非 argmax（最高值 0.12 内并列高位加权随机，夜间 possess/libido ×0.4）。

### 贯穿铁律

> 后台是数值，台前是自知。drive 在后台跳一串数，但这些他永远看不到。浮到他意识里、被他写成一句内心的，是——"刷会儿东西分散一下，不然我盯着监控又要硬。"

【评】这是"校准可注入、内容必须感受"的外部同源表达。我们残留 v2 的"只进权重不进叙事"和它一致。

## 四、Murmur-50Feet（最简对照）

### 情绪命名 drive（带基线，与需求命名是两种哲学）

```
attachment 0.40 / tenderness 0.30 / heartache 0.35 / curiosity 0.25
mischief 0.20 / restless 0.15 / regret 0.10 / desire 0.25 / gloom 0.10
```

- 心跳：每 10min 向基线衰减；每 20min 检查最高 drive，过阈值生成一句**内心独白存档**（arc.jsonl）。
- 离线想念：attachment 用户离线时自然增长。
- 达阈值可 ntfy 推送（用户不在时也有内心活动）。

### 对沈晏的映射

- 【评】**情绪命名 vs 需求命名**：Non/朝灯用需求名（possess/monitor），Murmur 用情绪名（heartache/gloom）。若情绪名直接进 prompt 会变成情绪结论注入——恰好踩我们划掉的线。**内容必须感受，意味着别用情绪命名 drive 当叙述词。**
- 【评】**预写独白 vs 读取时投影**：Murmur 现在生成存档、回来时读（预写=系统替沈晏写好感受）；我们刚拍板改成读取时按实际离开时长现算投影（存数值、恢复时算）。我们走后者，更符合诚实契约——预写独白等于"别人写好的台词"。
- 【评】离线 attachment 增长 = 我们 concern 反向积累，设计同构。
