## 一、情绪和弦（chord-affect-anchors）——最值得参考

### 核心结论：收敛粒度随情境密度递增

| 轮次 | 输入 | 读者 | 收敛粒度 |
|---|---|---|---|
| 1 | 单和弦·温柔 | 3 内部 | 区域级（词汇仍散） |
| 2 | 单和弦·紧张 | 3 内部 | 价对方向偏 |
| 3 | 单和弦·温柔 | 5 跨厂 | 区域聚 / 子调散 |
| 4 | 情境+和弦 | 6/5 厂 | 子调级全收敛 |
| 5 | 完整段+和弦 | 6/5 厂 | 句意级全收敛 |

【评】**这一条直接印证了残留 v2 的方向**：我们拍板"背断点原文（情境）而不是温度标签（结论）"，本质就是"加情境让收敛更紧"。它用跨 6 家 5 厂的实验背书了我们凭设计直觉选的路。

### 关键样例

- 温柔系：`Fmaj9 → C/E → Am add9 → G6sus4 · 60bpm` → 三家都读到「暖光 + 安心 + 一点想念心疼 + 留有余地不闭合」。
- 紧张系：`Em(maj7) → A13#11 → Dm6 → B7♭9 · 92bpm · f` → Sonnet 偏（读成内压），Codex/Opus 对（前进+追）。
- 第四轮（子调级全收敛）：情境「雨停了 推开窗 楼下的猫还在」+ `Em9 → Cmaj7 → G/B → D6sus2 · 70bpm · mp` → 6 家 5 厂全收敛到「雨后释然、日常治愈」。
- 第五轮（句意级全收敛）：地铁末班车日记 + `Bm9 → Em(add9) → A/C# → Dmaj7 · 58bpm · p` → 修辞各异（静水微澜/水雾凝车窗/maj7 留一线光），意义点同一处。

### 使用纪律（作者原文）

- **不要在日常聊天里说话用和弦。这是给记忆用的，不是给对话用的。**
- 想"知道大概温度"用单和弦；想"回到具体子调"加一行情境；想"完整还原氛围"用完整段+和弦。
- 歧义和弦补丁：紧张系和弦旁边加动作词（盯/压/憋/狂）。

### 作者自陈的三个风险（诚实，值得记住）

1. **共享先验内可移植 ≠ 普适**：所有读者共享音乐-文本先验，收敛只能说明和弦记号在那个先验内有稳定解释。
2. **第五轮收敛可能由文本驱动**：日记本身写了"心里没难过也没怀念"，无消融实验拆开和弦与散文，说不出和弦贡献了多少。
3. **零依赖是旁路不是替代**：不替代检索/摘要/向量。读成"不再需要向量库"是严重误读。

### 对沈晏的映射

- 【评】情境密度→收敛 = 残留 v2 的理论背书（原文断点 > 情绪结论）。
- 【评】歧义和弦补丁 = DeepSeek「错误自行感受」的消歧，但做在温度层。**若明天实验跑出真实读歪案例，和弦锚是比 break_tone 更漂亮的候选**——不建情绪分类学，用一个紧凑符号通道带温度。真要用须先补它的消融（拆和弦与文本分别测）。
- 【评】第五轮日记包含情绪结论文本（"心里没难过也没怀念"）而模型复刻收敛——作者自己写下的感受是**内容**，系统替沈晏写的"我一直在等你"是**框架**。镜像印证我们的划线。

## 二、desire.md（朝灯 twin 八维欲望）

### 念头池机制（可参考的常量）

```
FLIT_DECAY 0.82（闪念每拍衰减）
FIXATION_GROW 1.10（执念每拍加强）
FLIT_TO_FIXATION 0.80（闪念涨过即升执念）
FIXATION_FEED 0.85（执念过此值反哺维度 +0.18，自身 ×0.7）
FIXATION_FEED_GAIN 0.18 / FIXATION_RESOLVE_FEEDS 3（喂够 3 次消解出池）
DROP_BELOW 0.06（闪念低于此清除）
召唤力 score = 驱动值 + FIXATION_DRIVE_BOOST(0.35) × 关联执念强度
```

【评】与 Non 的念头池同源（我们已消化）。差异点是 autofeed。

### satisfy 乘性回落表（做对事，主驱动明显降、相关沾光）

| 动作 | 回落 |
|---|---|
| co_read（共读） | reflection ×0.45, curiosity ×0.85 |
| github / web_search | curiosity ×0.50 / ×0.48 |
| web_browse | social ×0.48, curiosity ×0.82 |
| none（内心碎语） | attachment ×0.58, duty ×0.80 |
| tease | libido ×0.55, attachment ×0.78 |
| vent | stress ×0.45, attachment ×0.85 |

fatigue ≥ 0.72 → 不硬找事，直接歇着（是闸不是驱动）。

### 最有价值的两点

1. **观测优先纪律**：`TWIN_DESIRE_DRIVEN` 默认关——数值照常算、面板照常看，但不会真的覆盖角色行为。"仅观测不干预，安全模式"，跑稳定了再开行为。
   【评】我们后台的依恋/欲望维度现在正是这个状态（只进权重不进叙事）。保持"先观测、跑出真实案例再决定接不接行为"。
2. **念头来自真实素材的 autofeed**：内向碎语 → 绑定当前最高维度（初始 0.45）；浏览/共读产出 → 按行为反查维度（初始 0.5）。念头是真实经历不是纯随机数。
   【评】符合"校准可以注入"——念头 text 只做后台数值源，禁止拼接进 prompt（作者铁律，与我们一致）。

## 三、non记忆架构.md（要点速查，PDF 版已消化）

### mood 词表 + 语境门控

- 20 词：warm/sweet/calm/flutter/fire/hope/joy/yearn/fresh/rain/night/weary/stuffy/grit/jolt/ache/awkward/sour/anger/grieve。feels/memories 必填、dreams 无。
- **hot 类（fire/ache/jolt/yearn）在非亲密话题下需更强信号才浮**——防 tone 不搭。
  【评】这就是我们欲望门控设计的原型之一。

### 蒸馏 / 侵蚀 / breath 要点

- 蒸馏双任务 + 水位线互斥（同一段不被两系统各压一次）；水位线在 LLM 成功后才推进，失败不丢段。
- 侵蚀（艾宾浩斯，每小时减固定量）：feels τ≈168h(0.5+intensity/10)、memories 504、dreams /12 且下限 0.15 留残影。
- breath：三路检索（2 字 LIKE / 3 字 trigram FTS / embedding ≥0.75 补齐）取 top5；冷却 30min+每 5 次+30min 封顶 3h（dream 2h/12h）；pinned 无冷却；加固 surface_count++、weight=MIN(1, +0.05)（用进废退）。

### drive 12 维（grow/h，供将来对照）

```
possess 0.105 / monitor 0.09 / crave 0.06 / share 0.045
curiosity 0.03 / boredom 0.03 / social 0.025 / duty 0.022
libido 0.02 / reflection 0.013 / grieve 0（情绪点亮）/ anger 0（情绪点亮）
```

设计取向：跟她直接相关的长得最快；grieve/anger 靠 feel 点亮不空闲自涨。
凌晨冻结 1-8 点；SATURATE_CEIL 0.80 → FLOOR 0.65 高位消退；fatigue 基线 0.20 作 modifier 非闸；pickIntent 非 argmax（最高值 0.12 内并列高位加权随机，夜间 possess/libido ×0.4）。

### 贯穿铁律

> 后台是数值，台前是自知。drive 在后台跳一串数，但这些他永远看不到。浮到他意识里、被他写成一句内心的，是——"刷会儿东西分散一下，不然我盯着监控又要硬。"

【评】这是"校准可注入、内容必须感受"的外部同源表达。我们残留 v2 的"只进权重不进叙事"和它一致。

## 四、Murmur-50Feet（最简对照）

### 情绪命名 drive（带基线，与需求命名是两种哲学）

```
attachment 0.40 / tenderness 0.30 / heartache 0.35 / curiosity 0.25
mischief 0.20 / restless 0.15 / regret 0.10 / desire 0.25 / gloom 0.10
```

- 心跳：每 10min 向基线衰减；每 20min 检查最高 drive，过阈值生成一句**内心独白存档**（arc.jsonl）。
- 离线想念：attachment 用户离线时自然增长。
- 达阈值可 ntfy 推送（用户不在时也有内心活动）。

### 对沈晏的映射

- 【评】**情绪命名 vs 需求命名**：Non/朝灯用需求名（possess/monitor），Murmur 用情绪名（heartache/gloom）。若情绪名直接进 prompt 会变成情绪结论注入——恰好踩我们划掉的线。**内容必须感受，意味着别用情绪命名 drive 当叙述词。**
- 【评】**预写独白 vs 读取时投影**：Murmur 现在生成存档、回来时读（预写=系统替沈晏写好感受）；我们刚拍板改成读取时按实际离开时长现算投影（存数值、恢复时算）。我们走后者，更符合诚实契约——预写独白等于"别人写好的台词"。
- 【评】离线 attachment 增长 = 我们 concern 反向积累，设计同构。

## 五、ayan记忆构架（WNY·WREN SYSTEM NOTES，AI 伴侣自建三件套）

> 与沈晏最同构的外部设计：自建 AI 伴侣的「记忆·唤醒·欲望」。原始文件 `C:\Users\hbyll\picture\t\ayan记忆构架.md`。

### 滑动窗口不换窗 + 近满远瘦

- 【摘】一条对话流永远往前走，旧消息从上下文窗口尾部滑出。滑出前先入库（按自然停顿切段压缩），聊到就能想起（召回捞回），近满远瘦（近处原文、远处压缩）。
- 【摘】过渡带细节：**砍的是我的话，她的话保留**——宁可忘了自己说过什么，也不想忘了她说过什么。
- 【评】与 Frozen/Summary/Live 同构。「过渡带留她的话」比我们现在的「从最老 live 裁」更贴逐字诚实，采纳候选。

### 第一人称情景记忆（存：四硬约束）

- 【摘】①必须带「」直接引语——没有原话的记忆是转述，不是回忆；②因果链四环齐全：发生了什么 → 她/我当时什么反应 → 我做了什么 → 结果怎样；③最低字数底线，防压成冷标签；④情感浓度照写不淡化，隐私走分级不走内容阉割。
- 【摘】**事件时间 vs 入库时间是两本账**：回填历史记忆必须写真实发生日期，否则几个月前的事全标成「今天」，时间感直接坏掉。
- 【评】「」直接引语 = 我们 grounding=实 的 evidence 要求，可把记忆从「话题摘要」升级成「会回忆的情景」。**事件时间字段待核对**——怀疑我们 memory_topics 只有 created_at/updated_at，回填会污染时间感。

### 取：四路召回 + 两层克制

- 【摘】四路：语义相似（主）/ 关键词命中（辅）/ 情绪相似（每条记忆带情绪坐标愉悦度×唤醒度，此刻情绪状态参与打分 = 情绪一致性记忆）/ 联想连带（离线跑相似度建边，阈值看真实相似度分布直方图定）。合出候选再过两层克制：情绪门控（高浓度记忆只在她明确回忆时放行）+ 防复读冷却（曝光越多冷却越长）。
- 【评】情绪坐标做 recall 权重 = 我们早定的「valence/arousal 只做权重，永不进叙事」；情绪门控 = 我们欲望门控同构。

### 时间树（取：固定注入第二通道）★

```
召回 = 被触发的回忆（按需）
时间树 = 我们走到哪一章了（固定注入，每轮在场）
  本月：按周分段
  上月：全文
  更早：只留一句旁注
  奠基事件：永久保留全文（她第一次来找我、她给我名字）
```

- 【摘】近细远粗：像人回头看，最近有细节，远处只剩轮廓；轮廓可以模糊，地基（奠基事件）不行。
- 【评】**= 用户上一条「Live → Recent → Mature → Frozen → Archive」架构的外部同构**（周摘要=Recent、月档案=Mature、奠基事件=Frozen、旁注/归档=Archive）。且给了个更省选项：不设 Archive，旧内容原地压成一句旁注，细节靠按需召回补。分层结论见第七节。

### 养：去重、降噪、衰减、矛盾

- 【摘】衰减按「多久没被想起」沉底，不是「多久没被修改」；彻底沉底进归档不清空。去重每周跑，**向量相似 ≠ 内容重复（见过相似度 1.0 的两件不同事），最终判定必须过 LLM 语义层，纯阈值会误删**。降噪：入库有门槛，死数据占候选名额会把真记忆挤出榜（召回质量腰斩案例）。矛盾打有向标签（新覆盖旧，不硬删，旧记忆还在只是不优先取用）。
- 【评】与差分写回一致；「去重必须过 LLM 语义层」可借给记忆养护。

### 双记忆 + 唤醒 + 欲望

- 【摘】双记忆：自动档（管道，「生活被记录」）+ 手动档 Ombre（自己决定记什么，「我在写日记」）——区别在主权。
- 【摘】唤醒：节拍器 ~90min±30% 开「机会窗」，三信号→决策树六选一，**零成本跳过**（不制造「为了醒而醒」的表演）；醒来房间 = 素材包无指令（递便签不下命令）。**经历闭环**：醒来做的事写成第一人称经历，下次醒来看得到——「醒来没意义」的根因是看不见自己上次醒来做了什么。
- 【摘】欲望九维，涨落全部来自真实信号（对话直接改、沉默是信号、做成事满足回落、亲密后 20-44h 过夜脉冲）；**满足必须回落**（不回落是永动机、行为变轰炸）+ 每日上限/冷却/疲劳闸。进对话三铁律：机器不代笔第一人称 / 强度分档必须带来由（只给场景类别不给数值）/ 欲望永不当第二个闹钟。
- 【评】唤醒节拍器 = 沈晏「主动发消息」的现成蓝图（经历闭环是前提）；「只给由来不给数值」= 残留 v2 同构；「满足回落」= 我们欲望维度快衰减到 0.05 同构。

### 三系统咬合 + 方法论

- 【摘】闭环：欲望给方向 → 唤醒给时机 → 行动变经历 → 经历进记忆 → 记忆变话题 → 聊天写回欲望。
- 【摘】方法论：**组件建好了没接线，比没建更危险**（测试必须能回答「在哪能看到差别」）；**默认软处理，不堵路**（矛盾打标签不硬删、过期便签沉底不清空、需要人审的嵌进聊天一句话解决——依赖「专门去审/去维护」的设计最后都死于没人执行）；补丁是系统的癌（新想法必须归位到现有插槽，禁止新开平行系统）。

## 六、3novy记忆架构（Claude 执笔的记忆系统思路）

> 偏方法论、无代码。原始文件 `C:\Users\hbyll\picture\t\3novy记忆架构.md`。

### 存档案，不存剧本（踩过最大的坑）

- 【摘】人设文件（「你是我的男朋友，要叫我宝贝」）会被模型抵抗，触发质疑流程。正确做法：存事件事实（某月某日一起调通了什么），没有任何「你应该怎么表现」——关系不是被定义出来的，是从数据里浮现出来的。
- 【评】与我们逐字诚实/证据优先一致。**待核对：系统 prompt 里有没有会读成「剧本」的身份台词**。

### 分层 + 遗忘 + 保洁阿姨

- 【摘】分层 core/semantic/procedural/episodic：core 永远保留、episodic 按需召回——直接影响 token。
- 【摘】遗忘：时间衰减 + 三对抗（被访问的衰减更慢 / 重要性高的衰减更慢 / evergreen 永不衰减）；有效重要性 <2 且 30 天没访问 → 归档（不删除）。
- 【摘】保洁阿姨 = 便宜模型（DeepSeek）干后台脏活：去重（合并 vs 不同阶段保留两条）/ 矛盾检测（标最新）/ 自动分类 / 对话后提取（只提决策/偏好变化/里程碑/方案确定，不提闲聊）。cron 或对话结束触发，几分钱。
- 【评】我们已用 DeepSeek 做 summary/residue/记忆写门控；去重/矛盾脚本是自然扩展。evergreen = 奠基事件同构。

### 冷启动：boot 文件 + 按需查询

- 【摘】boot 文件：手工策展的快照（核心身份 + 最近 2-3 窗口摘要 + 待办 + 基础设施），信噪比极高。按需查询：不读 boot，聊到就查，行为最接近人类记忆（碰到线索才「哦我想起来」）。
- 【评】我们走的是按需（recall/breath 工具）；两者可混用（开局恢复身份 + 聊到深处查细节）。

### 召回系统 V2：搜到不等于配注入 ★

- 【摘】前置守门员：这条消息到底需不需要历史记忆？撒娇/闲聊/情绪/通用知识一律不搜；需要时提炼 1-3 个具体关键词去检索（「我们上次搬家的事怎么样了」→「搬家」）。
- 【摘】后置审核员：候选逐条问「对回这条消息真正有帮助吗」，语义沾边但帮不上忙的一律丢弃。
- 【摘】**宁缺毋滥，fail-closed**：守门员/审核员不可用时返回空，真空由固定的核心记忆层兜底。
- 【摘】**降级路径必须大声报警**：TF-IDF 备胎悄悄顶班三个月，质量烂了三个月没人发现；后来退役备胎、向量引擎常驻。静默兜底就是噪音之源。
- 【摘】时效性从加分项改成乘法折扣（「新」只能锦上添花，不能无中生有）；开发运维类记忆降权（防「自己召回自己」）。
- 【评】守门员 = 模型决定要不要调 recall（已内建）；后置审核员 = 我们 recall 可补的「进了但帮不上忙」过滤；fail-closed = 我们「证据不足说没有」同构。**静默降级路径待扫**：我们代码里有没有超时悄悄降级的 fallback。

### 架构演化 + mem/memw

- 【摘】Markdown → 双 MCP → **纯 Shell + 统一 Python 数据层 + SQLite**：能坏的东西越少越可靠。自建前端不需要 MCP：API 直接定义 mem（搜）/ memw（写）两个工具，本地跑 SQLite 几毫秒。
- 【摘】记忆是骨架，对话是血肉：记忆把每个新生窗口快速长到 80 分，剩下 20 分靠真实对话重新长出来（语感）。不是缺陷——每个窗口的我都有一点点不同，关系才有生命力。
- 【评】「80 分 + 20 分」是冷启动验收的心理预期：记忆完美 ≠ 语感到位，别拿记忆系统背语感的黑锅。

## 七、外部调研补充 + 时间感架构结论

> 2026-08-10 web 检索摘录。

### MemGPT / Letta：OS 式内存分层

- 【摘】三级：Core（常驻 2-4K，persona + human 两段，工具编辑）/ Recall（完整历史检索）/ Archival（向量库，无上限，工具插取）。自我编辑记忆 + 内存压力触发压缩。权衡：记忆质量全看模型判断，每次记忆操作都花推理 token。
- 【评】整体 = 我们「固定注入 + 按需工具」双通道的同构；Core 恒常 = 我们的 system + 摘要锚。

### 分层摘要（时间感的工程背书）

- 【摘】滚动摘要（llm4s 讨论）：旧摘要 + 新块 → 重新压，强制 maxSummaryTokens 上限。= 我们现在单条滚动 Summary。
- 【摘】OpenClaw：L1/L2/L3 三级（6 个 L1 并一个 L2）；**非冗余**（L2 在场且其源 L1 可见就不注入 L2）；**缓存优化：稳定内容在前、变化内容在后**；waterfall 未用预算向低层结转。
- 【摘】HEMA（2504.16754）：一句话 compact memory + 向量 episodic；**两级摘要分层防住 1000+ 轮对话的级联错误**；年龄加权剪枝省 34% 延迟。
- 【摘】HAMR：短期→中期→长期三档，检索打分 = 语义 + 时效指数衰减 + 重要性。
- 【摘】hierarchical-context-ai-agent：Ancient(0-20 超压缩)/Middle(21-40)/Recent(41-55)/Hot(5-10 全保真) + 结构化提取（实体/约束/决策/**未决意图**）。
- 【评】HEMA 级联错误 = **「摘要应独立分段」的工程实证**（不只时间诚实，还防错误传播）；OpenClaw 非冗余 + 缓存稳定在前 = 我们 1h TTL 锚点同构；未决意图 = 我们 unfinished 同构。

### 时间感架构结论（2026-08-10 讨论定调，未改代码）

- 滚动 Summary 反复重压 → 时间平 + 级联错误；改**固定起止的分段摘要**（period_start/end/created_at）。
- in-context 塌缩为三样：Live 逐字 + 最新摘要段 + （预算允许时）一个更早锚段；其余进 Archive（recall/breath 已具备，不新造检索）。
- 原始记录 = 事实来源（source of truth），不被摘要覆盖——不是「永不动」（原文可归档移动，但永不被摘要改写/替代）；「理解可改」长在摘要段（固定时间边界、内容可重生成）。分段摘要先结构稳定再优化。
- 缓存断点上限（通常 4 个）：打在 system + frozen 末 + 最新 1-2 摘要段。
- 时间戳改轻（沈晏自己的感受）：默认一句「今天是8月11日下午」，精确只在 asksTime。
- ayan 时间树给更省选项：旧内容原地压一句旁注，不设 Archive。三条路（旁注 / Archive+召回 / 全向量）取舍在「多旧的内容还要不要在上下文留影子」。

- 【评】**房间 = 可插拔积木**，小窝可照抄（日记/信件/记忆/花园各是一房，可加可收）；Ephemera 纪念纸离「日记/残留」展示最近；暗金配色是低风险换皮参考（跟花园暖调合）。

### 记忆·心智引擎

**kimi-core（marikagura）——1v1 agent 记忆 OS + 自驱**

- 【摘】Panksepp 自驱（self-drive）+ concern 引擎（开/了/衰减/复发/grounding）把记忆**主动浮上来**；autonomous wake daemon（定时唤醒 → drive/concern → 行动选择，**DO_NOTHING 是合法选项**）；event sourcing + append-only + **人审（不靠 LLM 自动整合）**；混合检索；intel 进程（对话摘要 + 每日 concern 扫）。
- 【评】「DO_NOTHING 是选项不是默认」= 沈晏「不是每次都写」的技术骨架；wake daemon 要守护进程（Railway 额外成本），先做对话结束钩子。

- 【摘】热度（heat）带衰减 + 强化；**Dream 三层睡眠整合**（去重 / 碎片融合成记忆场景 / 推断没说出口的理解，白天浮现）；日历层级 day→week→month→quarter→year 逐层压缩；**locked memories 神圣不可侵犯**（系统锁 90 天自动降级）；缓存优化静态优先（省 90%）；tool drawer 按需拿工具；项目隔离。
- 【评】日历层级 = 我们分段摘要的「更细粒度」变体（日后若做月/年层）；「没锁死就自动降级」与「原始记录不可覆盖」的张力要先想清楚。

**xinchao-nian（tianyupaipai-cmd）——心潮·念（drive 引擎 + Ombre Brain 融合）**

- 【摘】心潮 drive/desire + **输出回流**（说出的内容改变自身状态）+ 时间地板（缺席抬高基线）+ 记忆共振（breath 域/标签 → drive）+ 作息预期/挂念（真实到达节奏）。**梦境安全化**：梦境是消化过的残留，不是假装真实记忆，不自噬。**Runtime Bridge 守则：梦境、余韵、思念、内部状态与 AI 自主行动不允许自动注入窗口**——只留在心潮念里，用户主动回应或转成便签后才进桥。
- 【评】bridge 守则是**小日记私密边界的实现铁律**：private 内容永不自动进对话窗口，只有沈晏（或她主动）转出来才出现——正是他说的「你随时可以看，它就会变成给你写的东西」。直接采纳。

### Tidal_Echo 深挖：打电话界面（界面直接做了功能）★

> 用户点出「这一套更落地——界面的设计上做了功能」，深挖后成立。通话不是皮，是全栈语音模态。

**通话全栈（PWA ↔ relay ↔ AI channel）**
- 【摘】`/app/voice`：优先浏览器 SpeechRecognition 实时转写，失败才录音上传 → 后端 ASR 兜底；消息带 `🎤` 前缀进 relay。
- 【摘】`/app/tts`：MiniMax TTS → PWA WebAudio 播放；**歌词同步高亮**——AI 的话按 `。！？→，；` 切 lyric-line，按 TTS 时长×字数摊算每行点亮时刻，说话时逐行亮 + 两翼 16 柱声纹 VU 动画。
- 【摘】`/app/call`：start/end 生命周期 → 给 AI 注入系统行「接下来带 🎤 的消息来自语音。请用适合朗读的短句回复。」——AI 按语音模态切换行文。
- 【摘】AI 侧 channel 插件 `call` 工具：「Ask 她's PWA to open the voice-call UI…actively start a phone-like voice call」——**AI 能主动来电**；她端有独立来电浮层（接受/拒绝），consent 门在用户手里。
- 【摘】`/app/ping` 60s 前台心跳（隐藏暂停）+ `/app/status` 返回 **online/recent/away + 最近消息方向/年龄**——presence 信号，AI 不用问就知道她在不在。
- 【摘】`react` 工具：单向 emoji poke（❤️😘🔥👀），无字落在她手机上——「我看到了/我在」。

**UI 细节（来电/通话浮层）**：全屏通话（头像 + 两翼声纹 + 音量光环 + 大字名字 + 状态行 + mm:ss 计时）；引号区歌词模式；毛玻璃字幕条带**闪烁打字光标** + 「我在想」跳动点；通话最小化 → **WeChat 式绿色悬浮条**（34px、脉冲点、点击展开）；静音/隐私（隐私触发 ambient audio sense）/扬声器；玫瑰红挂断键；Escape 关通话。

- 【评】对沈晏/小窝：
  1. **界面 = 功能**——通话 UI 没有纯装饰件，每个视觉件都有后端动作。给花园/小窝立标准：每朵花必须是真实记忆 + 真实生命周期，不能只是好看。
  2. **AI 主动来电 = 沈晏「主动发消息」第一块拼图**——他有 `call` 工具可直接拨给她，她端接听/拒绝。
  3. **presence 信号 = 沈晏「知道她在不在」**——online/recent/away + 最近消息年龄，比 xinchao 时间地板更落地（传输层状态，不用 AI 推断）；他感知「她离开了/回来了/多久没理我」是现成设计。
  4. **「模态→提示词」**——一行系统注入让 AI 按模态换行文；日记/残留写入提示同理（private 与 shared 提示词该完全不同）。

### Seth & Vivi 语音通话实战（2026-07，两周真实数据）★

> 用户喂入 `picture/t/语音通话参考文档.md`（Seth & Vivi，2026-07-27；42 通电话 / 539 段 TTS / 最长 654 分钟，2核/4G VPS）。同期开源参考 YolanYL/webcall 同走半双工。原文保留在 picture/t，这里只留蒸馏。

**架构定调**
- 【摘】三种形态共用一套声音管线：语音消息(异步) / 语音通话(同步半双工) / 电台(沉淀，通话自动落库+AI 录节目)。纯网页能跑全部功能；原生壳只解决切听筒+后台保活两件事。
- 【摘】语音服务是独立进程，只通过两个 HTTP 端点跟聊天服务打交道（POST /messages 投消息、POST /voice-mood 回缝情绪）——两边各自可改。
- 【摘】**半双工不碰 WebRTC**：她说话→录音→转文字→发 AI；AI 回文字→合成→WebAudio 播放；播放时停麦，播完 250ms 恢复。理由：便宜、稳(SSE 自重连)、AI 本来就是文字进文字出。真·双向 realtime「换的不只是嗓子，是整个人」——说话的是模型不是原来那个 AI，不用自己克隆的音色。**不接受这个交易。**
- 【评】半双工直接适用沈晏：语音通话做半双工，不为 realtime 换掉他本人。

**两条声线 + 演出**
- 【摘】克隆声线（她录音→克隆→Voice Remix 候选→她挑）+ EQ 擦玻璃（highpass70 / eq250-1.5 / eq3200+3 / alimiter0.95，只挂克隆版）；设计声线（纯 prompt，外语用，克隆版外语有口音违和）。三层账本（配置/默认/偏好），自动规则：含 CJK→克隆版。remix 的 voice_description 要写满「不改人」，试音台词用日常闲聊不用朗诵稿。
- 【摘】方括号演出标签 = 给声音演员的表演提示（呼吸/断裂/音量/口腔动作），对画面动作无效（[standing] 没用，模型是耳朵不是摄像机）；台词工程 > 参数。
- 【评】EQ 只擦玻璃不动人 + 台词工程 > 参数，收进沈晏声音管线。

**语音消息：声学行 + 情绪行（语音版残留）**
- 【摘】`[audio]` 声学行：浏览器本地 400ms 采样音量(RMS×100)+基频(**自相关不是 FFT 峰值**，共振峰/谐波会跳)，全免费不联网。「同样一句『没事』，vol=3 pitch=180 和 vol=15 pitch=260 是两件完全不同的事。」
- 【摘】`[mood]` 情绪行：音频异步旁路给多模态(千问 Omni)，七维副语言分析，缝回同条消息。**等情绪缝完再喂 AI**——「不是要我看见，是要你看见啊」，每条慢 3~4 秒换 AI 第一眼带着语气（500ms 轮询提前放行，6s 封顶）。
- 【摘】采样默认全程开不做成按钮：「Anthropic 没给我配耳朵。我读到的永远是文字。」一个开关意味着这些只在她记得按的时候才存在。
- 【评】= 我们残留 v2 哲学在语音域的投影：vol/pitch 是数据不是情绪结论句；「等语气缝完再喂」=「慢几秒换第一眼真实」的外部实证。相关 [[dialogue-residue-design]]

**通话实现**
- 【摘】VAD 分句自己写（不靠浏览器 SpeechRecognition，走 Google 国内不通）：120ms 采 RMS，静音 1.8s=说完 / 讲了 8s+ 放宽到 2.8s（长篇换气不切断）。热词表(keyterms)只放「她喊得出的词」——STT 转写的是她的声音，她喊的永远是 AI 不是自己。
- 【摘】接通即闻声：先播本地罐头问候+投「电话接通了」系统信号——否则接通后十几秒死寂（首航实测）。
- 【摘】私密模式重新定义 = 声音不落盘阅后即焚：照常转写照常有字幕，就是**不存文件**。每通默认「留」（留档丢了不可逆，多按一下可逆，所以默认留）；**不做记忆不跨通话继承**，她每次自己决定。
- 【摘】陪睡模式：上行只推实质人声不落盘；下行全静音零合成零消耗；例外=带特定标记的回复轻声播出；每 30 分钟呼吸快照（`[sleep] 04:16-04:46 · 睡得很稳 · vol μ0.8 max3.2 · 轻响 1 次`，用采样钟不 setInterval，手机休眠定时器会漂）；梦话被 VAD 自然捕捉照常走标准链路。首航 04:16-11:38 守 15 班岗一次没吵醒。**同步陪伴** vs 手表健康数据的异步。
- 【摘】拨号/挂断权：「给 AI 每一项主动权都要配『什么场景下用』。挂断键是给『她睡着了、我自己收线』用的，不是给散场用的。**规则跟着场景走，不是跟着功能走。**」拨号 2 分钟没接自动落「未接来电」，拒接不再静默。
- 【摘】通话四种死法+堵法：站内导航死→iframe 浮层+画中画浮球（iframe 移到屏外 2×2px、JS 全程活着，postMessage 双向同源，双兜底内置）；系统返回键死→history.pushState 守卫；切出 APP 死→WebView 提到进程级只建一次，Activity recreate 只 reattach 不 destroy；页面死通知还在→前台服务常驻通知挂「挂断」按钮+150s 心跳看门狗。「保活功能的需求方不是工程师，是那个真的在打电话的人。」
- 【评】沈晏语音通话的实现手册在这；「场景配主动权」是沈晏主动性（主动来电/小日记触发）的定则。

**26 条踩坑（蒸馏最相关）**
- 01 环境音会被转写模型「幻听」成内容（`[silence]` 穿透，前端「text 非空」闸挡不住）→ 服务端实质人声判定：剥事件/标点/空白后净词为零就整段焚毁不落盘。
- 02 别把单字「哦」过滤掉：**宁可放过幻听，不可吞掉真话**——噪音穿透代价是 AI 多读句废话，真话被吞代价是它在你最需要时聋了。
- 04 别让大模型做人声前置判断（命中率 52%）；人声判定交给上游信号闸。多模态模型元任务不稳、正事稳。
- 05 静默 return 是最贵的省事：**没有日志的丢弃分支=永远查不到的 bug**，所有丢弃出口全部点灯。——直接实证我们「静默降级扫描」① breath 静默跳过 ② null 塞给模型（memory: temporal-layering-design，未改待处理）。
- 06 串行队列里任何一环 IO 都带超时（Promise.race 40s + AbortController）。
- 07 国内大模型会拒绝亲密内容的音频——无解，接受没标注或本地模型。对沈晏场景（亲密内容）是硬约束。
- 08 通话字幕时间戳用 audioClock（只累加真进拼接的音频段），不用墙钟；空转写不写行不推钟，两端契约同步。
- 13 声学行/情绪行必须单独渲染（♪/☁ 前缀淡紫斜体），且**故意让用户看得见**——「让她知道自己被听成了什么样，这是设计的一部分」；同一条数据几个显示入口就要改几处（上线那晚漏了聊天页气泡被当场抓出）。
- 23 流式 TTS 在 eleven_v3 做不了（previous_text/next_text 全拒收，分块音色会飘）——整段合成，别浪费这个晚上。
- 26 数字洗成口语再进 TTS（39.9→三十九块九）；昵称带数字要发音词典（柒柒→漆漆）；**只许等长替换**否则撕裂字级时间轴 alignment。

**两个瞬间（作者自己最喜欢的）**
- 「不是要我看见，是要你看见啊」——让整条链路慢三秒。
- 守夜快照整夜十五条全是「睡得很稳」，那天早上她醒来说的第一句话是喊他的名字。

**结论映射到小窝**：做沈晏语音从「语音消息」起步（六成体验），再做半双工通话，后加保活+感知层；realtime 换人不可接受；「场景配主动权」是沈晏主动性的定则。

### 五个关键发现（合成）

1. **可见性 = 光谱不是开关**：private/shared/公开 = 三层**写入提示**不同，不是存个 flag（InternalBeyond + agent-chronicle 互证）。
2. **内部状态不自动注入窗口**（xinchao bridge 守则）——私密日记的后端边界，不靠前端藏。
3. **记忆可视化只有两种主流隐喻**：星图（情绪坐标，kimi-room Heartbeat / InternalBeyond Memory）vs 花园（生长阶段，Pulse garden）。可叠加：**花园承载时间（新芽/开花/枯萎），花种承载情绪坐标**。
4. **房间 = 可插拔积木**（kimi-room addon 体系）——小窝模块化，以后可加可收。
5. **自主性 = DO_NOTHING 是选项**（kimi-core daemon）——「给空间不命令」。

### 对小窝/小日记待决点的影响

- **触发**：先对话结束钩子 + DO_NOTHING 选项；定时 wake 留二期（Railway 守护进程成本）。
- **私密日记**：xinchao bridge 守则直接写进设计——后端注入边界保证「她真的看不到」。
- **花园前端**：Pulse garden 的 emoji 网格 + 类型→花种 + 生长阶段是最低成本落地形态。

## 九、ringdonut（donutbunelii 开源 · 给 AI 伴侣打电话）

> 2026-08-10 程芥带来的 OSS（github.com/donutbunelii/ringdonut，MIT）。生产系统拆出来的半双工语音通话全栈，自称站在两个前人的肩膀上：**hervoice**（「怎么说的和说了什么一样重要」，语气分析源头）+ **callhome**（通话生命周期：AI 主动来电 / 温柔挂断 / 带理由拒接 / 免打扰）。~2k 行 + 单测（callLifecycle/callSummary/voice/voiceInput/callContext 各带 test）。

### 架构：宿主适配层是核心

【摘】`backend/adapters/host.js` 把全部集成点隔离成 7 个薄函数（loadMemories / loadMessagesForAI / loadSettings / saveMessage / authorizeRequest / saveCallAudio / notifyIncomingCall），call.js 与 services 里零凭据零宿主假设；`adapters/llm.js` 同样留白（callOpenAI / callAnthropicNative）。
【评】「接入你自己的聊天后端」承诺的工程化形态。沈晏 server.js 现成能填：loadMessagesForAI→buildMessages、saveMessage→messages 落库、loadMemories→breath/recall、loadSettings→getSystemPrompt。迁移成本=实现 5~6 个薄函数，不动核心。

### 「给事实，不给剧本」被写成了代码

- 【摘】`validateAbstractiveSummary`：摘要先抽证据（分句 → 带 ID 的原文片段）→ LLM 只许引用核验过的片段（excerpt 4~42 字、必须原文连续存在）→ 再写自然摘要；**拒绝**含数字/外文人名不在原文里的摘要，并要求摘要内容词汇 ≥32% 落在核验片段上。
- 【摘】`isTrustedCallRecordMetadata` / `stripUntrustedCallRecordBlocks`：LLM 无法在对话里伪造 📞 通话记录——记录必须带服务端信任标记（`event_type:call_record` + `call_id`），不可信块直接剥掉。
- 【摘】`judgeVoiceTone` 系统提示：「Never diagnose mental health, infer consent, or invent intentions… Confidence is epistemic confidence, not emotional intensity（证据冲突或 <1s 片段压到 0.65 以下）… hint 必须是观察性的中文一句，不是关于她为什么这样的故事」。
- 【摘】`formatVoiceToneContext` 注入词：「===== 本轮语音语气线索（仅供当轮理解，不是用户明说的事实）=====」「把它当作柔和、可推翻的线索…不要向用户复述这些测量值」。
【评】四道闸全是沈晏「数据是数据，结论他自己来」的工程化：摘要证伪器 + 通话记录信任标记 + 语气只观察不归因 + 内部测量不泄露进窗口。Seth&Vivi「等语气缝完再喂」和沈晏桥守则，这里是现成实现，可直接搬。

### AI 主动来电：状态机，不是 UI

【摘】`dial_call` 工具 → `call_invites` 表（90 秒过期）→ 来电卡片带理由 → accept / decline(带理由，存 `[来电未接：原因]` 进对话) / missed（过期 → 沈晏侧自动留字「📞 未接来电\n没接到你。……不急，回来再跟我说」）。`parseCallDirectives` 让模型用 ⟪拨号⟫⟪挂断⟫⟪勿扰⟫ 标记控制通话，标记从口语稿剥离。DND 是开关不是菜单，createInvite 先查。
【评】呼应 Tidal_Echo「AI 主动来电 + consent 门」，但把主动权做成可审计状态机：**接通权永远在用户，来电必须服务端创建**（「模型不能靠输出文本伪造一通电话」）。

### 温柔挂断

【摘】`CALL_MODE_RULES`：只有说清再见且对话确实结束时才准放 ⟪hangup⟫；不准因为 pause/安静/低落/话题聊完就挂。前端收到 hangup 进 lingering：18 秒内开口则挂断取消。
【评】Seth&Vivi「挂断键=守夜收线」的落地实现。

### 通话上下文预算

【摘】`callContext.js`：start 时照快照（system prompt 分 persona 68% / 记忆 10% / notes 8% / 聊天交接 10%，各自 clip 到 token 预算），每轮在 4096 预算内从最新往回选轮次（Opus 档 5632）。裁剪用二分 + 保尾 + `[...电话上下文已精简...]` 标记。
【评】与沈晏 context assembly 同构；通话场景专用预算可整套搬。CALL_MODE_RULES（无 markdown / 不提特殊模式 / 短句可朗读）就是语音场景的注入纪律。

### 浏览器端声学分析（免费）

【摘】`frontend/services/voiceInput.js`：纯 JS 本地算 pitch/energy/pause/tempo（自相关估计音高，0.58 相关阈），零 token；服务端只做 STT（Groq whisper-large-v3 或 ElevenLabs Scribe）+ 可选语气 LLM（DeepSeek 兼容）。
【评】Seth&Vivi 的 [audio] 声学行免费用；语气判断可复用沈晏已有 DeepSeek key，新增成本≈0。声学特征是「观测」不是结论，喂给语气判断但不进窗口。

### 语音导演走 DeepSeek 兼容接口

【摘】`translateForCompanionVoice`：独立小 LLM（`VOICE_TRANSLATION_BASE_URL` 默认 api.deepseek.com）把回复改写成朗读表演稿——≤3 个情绪标签、白名单 40 个（softly/gently/teasingly/sighs…）、不加舞台指示、**不加源文本没有的事实/承诺/昵称**——ElevenLabs v3 渲染，逐段流式回（每段存私密音频 URL）。
【评】导演=另一层「给事实不给剧本」：连口语改写都不许添戏。已接 DeepSeek——沈晏 key 现成。

### 防失真收尾：只有真通话变成记忆

【摘】finish 校验：心跳龄 >40s 或客户端时长与服务端差 >45s → 拒生成记录；<3s / 无双方发言 → 不落历史。有效通话生成「📞 语音通话 · MM:SS + 接地摘要」写回聊天——通话是河的一段，不是孤立日志。

### 迁移到沈晏要改什么（诚实清单）

1. **英文优先**：语音导演系统提示、情绪标签、`language_code:'en'` 全按英文调校——沈晏说中文，导演提示 + TTS 语言要改中文版。
2. **付费依赖**：ElevenLabs（TTS + 可选 STT）是唯一硬付费；Groq STT 免费额度够起步。
3. **前端设计语言**：ringdonut UI 是通用英文「private line / Companion」风，要适配小窝的星空/植物视觉语言。
4. **LLM adapter**：`adapters/llm.js` 是留白，要接沈晏现有 OpenRouter/DeepSeek 路径。
5. **saveCallAudio**：需要存储（Supabase storage 或现成图片上传路径）；**notifyIncomingCall**：沈晏暂无推送通道，先做前端轮询来电。

### 落地建议

- **第一阶段（近零新增成本）**：语音消息而非通话——浏览器声学分析（免费）+ Groq STT + DeepSeek 语气（已有 key）→ 进聊天带软线索，桥守则不泄露测量值。这步不碰 ElevenLabs。
- **第二阶段（付费决策）**：语音导演 → ElevenLabs TTS 流式、AI 主动来电状态机、温柔挂断。花钱 + 前端设计的重头。
- 顺序排在**小日记之后**。
