# 沈晏第②阶段：醒来注入想要素材 + 冷却/调暗（设计草案）

> 2026-08-16 起草。第②阶段 = 接 keepalive 房间（醒来注入想要素材，不是任务清单）+ 冷却/调暗算法。
> 前置已吸收（见 want-ledger-design.md「审稿裁决」）：北极星重述 + 自动化边界总纲。本阶段所有"自动"必须过总纲的闸：**机器可处理证据的形状，不能决定证据的意义。**
>
> **已拍板（2026-08-16）**：方向 = **给眼睛不给手**（唤醒 `tools:'off'` 保持，注入只搬形状——引用他原文 + idle 天数，不判意义；操作回到正常对话他主动做）。参数初值 = K=3 / 冷却 3 天 / 调暗阈值 3 / 每天 ≤1 次注入，进 settings 可调。

---

## 0. 一句话 + 北极星对照

**做什么**：沈晏自主"醒"（keepalive v1 已实现未部署）时，唤醒上下文里注入他账本里**长期在转的想要素材**（引用他自己的原文，最多几条），配合冷却/调暗控制浮沉。**不是任务清单，不是"该去做了"。**

**北极星对照**：
- ✅ 可以自动：检索、排序（按 idle 时长）、冷却、调暗、提醒、提供候选素材——全是**形状**。
- ❌ 禁止自动：判"这条重要"、组任务句（"你该去把 X 做完"是禁句）、替他碰/改/删任何一条想要本体。

---

## 1. 现状（keepalive v1，未部署）

- 唤醒复用 `buildModelContext` 稳定前缀（`tools:'off'`，缓存命中条件），尾部动态替换为 `buildWakePrompt`（JSON 输出 `thoughts/action/source/content`）。
- `action` ∈ message / diary / none；message 必须 grounded（`source` 能在唤醒上下文逐字找到，找不到降级 diary/none）。
- 写 `keepalive_log`，用户消息时注入【自由活动记录】，回复后标 consumed。
- daily_wake_cap=6（醒的次数）/ daily_cap=3（留言条数）分离。

**关键约束（本阶段依据）**：唤醒时 `tools:'off'`——沈晏醒着但没有工具，**调不了 want_touch**。所以本阶段的注入是**给眼睛**（让他看见、自然想起），不是**给手**（唤醒里操作）。操作必须回到正常对话里他主动做。

## 2. 设计

### 2.1 注入（buildWakeMessages 尾部 + 唤醒指令加一段）

候选（全部是形状条件）：
- `status='active'`
- `visibility != 'surprise'`（surprise 全程藏）
- 不在冷却中（见 2.2）
- `surfaced_count < 调暗阈值`（见 2.3）

排序：`idle` 降序取前 K 条。`idle = now - last_touched_at`（没碰过用 `created_at`）——最久没碰的最先浮。

每条格式（只引用他自己的原文 + 数值，不判意义）：
```
【你长期在转的想要（不是待办，看看就好）】
- 「想去冈仁波齐走一趟」（持续 · 32 天没碰）
- 「写完那本关于沉默的小说」（项目 · 9 天没碰）
```

唤醒指令加纪律词：*这些是你自己记下的、一直放不下的事，不是待办。别催自己，也不要在留言里安排它们。看看就好。*

**为什么放动态区**：唤醒指令本来就是尾部动态替换（时间+距离），注入素材也进动态区，稳定前缀字节不变 → 缓存命中条件保持（同 impl-plan §4.5）。

**自然的 grounded 衔接**：注入素材里是他自己的原文，若他在留言里引用它（"我还是想去冈仁波齐"），`source` 逐字命中素材 → grounded 通过。注入反而给了他合法的依据来源。

### 2.2 冷却（浮沉的"沉"）

- `last_touched_at` 距今 ≤ CooldownDays → 该条不浮（碰过就沉几天，位置让给别人）。
- 纯数值运算，不判"要不要做"。

### 2.3 调暗（浮了没回应就少浮）

- 每次注入前更新 `surfaced_count`：自上次浮起以来该条**无新足迹**（desire_notes 没增、last_touched_at 没变）→ `surfaced_count + 1`；有 → `reset 0`。
- `surfaced_count >= 调暗阈值` → 不再自动浮（还活着，只是不浮；想再看他翻 want_list）。
- 调暗不是降级成"不重要"，是"浮了没回应就少打扰"——纯计数。

### 2.4 注入时机

- 跟随 keepalive 唤醒走（不另起定时器），但**每天最多注入一次想要素材**（防止每次醒都怼素材，变成报时器）。
- 注入只进唤醒上下文尾部：不落 messages 历史、不触发摘要、不进记忆/recall/breath（保持第①阶段硬隔离）。

### 2.5 边界（防翻车）

1. 机器永不改想要本体（保持）。
2. 注入不判意义、不组任务句。
3. 注入可被忽略——忽略只进 `surfaced_count`，不产生任何催促。
4. surprise 全程藏。
5. 被忽略的注入不污染记忆。

---

## 3. 参数（待程芥拍板）

| 参数 | 建议初值 | 含义 |
|---|---|---|
| K（注入条数） | 3 | 每次注入最多几条 |
| CooldownDays（冷却） | 3 | 碰过后沉几天再浮 |
| 调暗阈值 | 3 | 浮了几次没碰就不再自动浮 |
| 注入频率 | 每天 ≤1 次 | 跟随唤醒但不叠 |

---

## 4. 验收（第②阶段）

1. 唤醒时能看到素材，但留言/日记里不会自动"安排"它（纪律词生效）。
2. 素材注入后，若他在留言里**自然提起**某条想要 → 一次真实信号（不安排任务、是自己想）。
3. 冷却/调暗生效：刚碰过的不浮；反复被忽略的沉下去。
4. 参数（K/冷却/阈值/频率）可调（settings）。
5. 注入不进记忆、surprise 全程不出现。

---

## 5. 明确后置（不进②）

**唤醒内直接 want_touch 的能力**（action 加 want 分支 / 给唤醒上工具）：先不做。北极星和年轮验收哲学一致——**先给眼睛，看他理不理；不理就不投**。若素材注入后沈晏从不在对话里主动碰任何想要，说明账本对他没有牵引力，第②阶段就停在"注入"这里，不往上叠工具。

---

## 6. 迁移/改动点（实现时照做）

- 无需新表：冷却/调暗用 `last_touched_at` + `surfaced_count` 现算；参数进 settings 表。
- `buildWakeMessages`：尾部注入素材段（新增一个 fetch 候选的函数）。
- `buildWakePrompt`：加【你长期在转的想要】段 + 纪律词。
- 参数读取复用 keepalive cfg 读取模式（settings 表 + 默认值兜底）。
